The Pepper Programming Language

Built-in functions

assert and panic, which every program can call without an import.

Source: runtime/internals.pep

assert

assert(condition: bool, message: String)

Panics with message when condition is false; otherwise does nothing.

The check always runs; there is no release mode that removes it. A string literal message picks the __ptr<char> overload instead, which builds no String. Any other message is evaluated before the call.

Parameters

  • condition — the condition that must hold
  • message — the text to print on failure; a null String prints a generic message

Panics

  • if condition is false: prints the location and message, and aborts (see panic)

Example

assert(count > 0, "count must be positive");

assert

assert(condition: bool, message: __ptr<char>)

Checks that condition holds; if not, panics with message, a NUL-terminated C string. A string literal message picks this overload, so an assertion that holds builds no String.

Parameters

  • condition — the condition that must hold
  • message — the text to print on failure, or __null for a generic message

Panics

  • if condition is false: prints the location and message, and aborts (see panic)

Example

assert(count > 0, "count must be positive");

panic

panic(message: String)

Prints message and aborts the program. It never returns.

Flushes every C output stream, so output printed so far is not lost, then writes location: panic: message and a newline to standard error ("Assertion failed with no additional information" when message is null), followed in a build without -O by a backtrace of the calls that led there (PEPPER_BACKTRACE overrides the build; see the debug module's print_backtrace), and calls C abort(). No destructors or releases run, and the process ends abnormally (SIGABRT on POSIX).

The location is the call's file:line:col, which the compiler passes in a hidden parameter, the way a C++ std::source_location default argument works. A function that panics on its caller's behalf, as the runtime's indexers do, declares that parameter itself and passes it on, so the panic names its caller's line:

check_positive(value: int, location: __ptr<char> = __caller_location()) {
    if (value <= 0) {
        panic("expected a positive value", location);
    }
}

Parameters

  • message — the text to print

Panics

  • always

Example

panic("unreachable");

panic

panic(message: __ptr<char>)

Reports message, a NUL-terminated C string (a generic message when it is __null), as a panic and aborts, as panic(String) does. A string literal message picks this overload, so it allocates nothing.

Parameters

  • message — the text to print, or __null

Panics

  • always

Example

panic("unreachable");

PanicHook

type PanicHook = shared (String, String) => void

The function a panic runs before it prints its message: see set_panic_hook. It receives the panic's message and its location (file:line:col, or an empty string when the panic has none).

set_panic_hook

set_panic_hook(hook: PanicHook)

Installs hook as the process's panic hook, replacing the one installed before (take that one with take_panic_hook first to chain them).

Every panic, on any thread, calls the hook on the panicking thread before it prints its message and backtrace, then prints and aborts as always: the hook cannot stop the panic. A full-screen terminal program uses it to leave the alternate screen, so the message lands where the user can read it. That covers panic, a failed assert, an index out of range, an overflowing operator and every other check the compiler or the runtime adds. A stack overflow skips the hook: the thread has no stack left to run it on.

A panic inside the hook does not run the hook again: it prints the first panic's message, then its own, and aborts. Two threads that panic at once each run the hook, at the same time. Keep the hook short, and keep it from taking a lock the panicking code may hold: it would wait forever instead of letting the program end.

Parameters

  • hook — runs with the panic's message and location

Example

var previous = take_panic_hook();
set_panic_hook((message, location) => {
    leave_alternate_screen();
    previous(message, location);
});

take_panic_hook

take_panic_hook(): PanicHook

Removes the process's panic hook and returns it, so that a panic again only prints its message.

Returns

  • the hook set_panic_hook installed last, or one that does nothing when there is none

Example

var hook = take_panic_hook();   # panics no longer run it
set_panic_hook(hook);           # and now they do again
