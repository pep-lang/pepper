The Pepper Programming Language

Map and Set

Sorted collections: Map<K, V> and Set<K>, kept in key order on a red-black tree, and compare<T>, the ordering they sort keys by.

Source: runtime/map.pep

compare

compare<T>(a: T, b: T): int

Returns a negative number when a sorts before b, zero when they are equal, and a positive number when a sorts after b: the order Map and Set keep their keys in.

The generic version compares with <, so it works for every Comparable type (see Comparable), every integer type, char, and any struct that declares a < operator. Two values neither of which is < the other are equal keys. String, float and double go through concrete overrides that call their compare, so a NaN key sorts after every number instead of breaking the order.

A struct with no < operator declares Comparable, or overrides this function for itself, to be a Map key or Set element: compare<Point>(a: Point, b: Point): int. The order must be a strict weak order (consistent across calls), or the tree loses track of its keys.

Type parameters

  • T — the type of the values to compare

Parameters

  • a — the first value
  • b — the second value

Returns

  • a negative number, zero or a positive number as a sorts before, equal to or after b

See also

  • compare<String>

Example

assert(compare<int>(1, 2) < 0, "1 sorts first");
assert(compare<int>(2, 2) == 0, "equal");

compare

compare<String>(a: String, b: String): int

Compares two Strings by content, the order Map and Set keep String keys in: the same as a.compare(b).

Parameters

  • b — the second String

Returns

  • a negative number, zero or a positive number as a sorts before, equal to or after b

Example

Map

struct Map<K, V>

A map from keys of type K to values of type V that keeps its keys sorted.

Keys are ordered by compare<K>: numbers by value, String by content, and other structs by their < operator or a compare<K> override. Two keys that compare equal are the same key. Lookups, inserts and removals take O(log count) time on a red-black tree.

iterate() visits the entries as (key, value) tuples in ascending key order, reversed() in descending order, and range(from, to) the keys from from up to (not including) to. first, last, lower_bound and upper_bound find single entries by order.

The map holds one reference to each stored key and value. It acquires them when they are stored and releases them when they are overwritten, removed, cleared, or when the map is destroyed.

For keys kept in the order they were inserted, use OrderedMap; for expected O(1) lookups in no order, HashMap.

Type parameters

  • K — the key type; ordered by compare<K>
  • V — the value type

Example

var scores = Map<String, int>();
scores["carol"] = 91;
scores["alice"] = 84;
scores["bob"] = 77;
for (var (name, score) in scores) {
    print($"{name}: {score}");   # alice, bob, carol
}

iterate

iterate(): SortedMapIterator<K, V>

Returns an iterator over the entries as (key, value) tuples in ascending key order; for (var (key, value) in map) drives it.

The iterator holds a reference to the map. Changing a value through an existing key while iterating is allowed; adding or removing an entry makes the iterator's next next() or current() panic.

Returns

  • an iterator positioned before the first entry

reversed

reversed(): SortedMapIterator<K, V>

Returns an iterator over the entries in descending key order, under the same rules as iterate.

Returns

  • an iterator positioned before the last entry

Example

for (var (name, score) in scores.reversed()) {
    print(name);   # carol, bob, alice
}

range

range(from: K, to: K): SortedMapIterator<K, V>

Returns an iterator over the entries whose keys are at least from and less than to, in ascending key order, under the same rules as iterate. It is empty when from is not less than to.

Parameters

  • from — the smallest key to visit
  • to — the key to stop before

Returns

  • an iterator positioned before the first entry in the range

Example

for (var (name, score) in scores.range("a", "c")) {
    print(name);   # alice, bob
}

copy

copy(): Map<K, V>

Returns a deep copy: a new map holding a copy of each key and value, made with copy. This is how copy(value) copies a Map (the Copyable<Map<K, V>> implementation); call copy(map) rather than this method. O(count log count) plus the cost of copying the entries.

Returns

  • the copy

SortedMapIterator

[Value] struct SortedMapIterator<K, V>

An iterator over the entries of a Map as (key, value) tuples, in key order or reversed; returned by Map.iterate(), reversed() and range(from, to), and driven by for (var (key, value) in ...).

Holds a reference to the map. It is fail-fast: adding or removing an entry after the iterator was created makes its next next() or current() panic.

Type parameters

  • K — the key type of the map
  • V — the value type of the map

Set

struct Set<K>

A set of distinct elements of type K kept in sorted order, on the same red-black tree as Map but without values.

Elements are ordered by compare<K> (see Map); two elements that compare equal are the same member. Membership tests, inserts and removals take O(log count) time. iterate() visits the members in ascending order, reversed() in descending order, and range(from, to) the members from from up to (not including) to.

The set holds one reference to each member, acquired on insert and released on remove, on clear, or when the set is destroyed.

Type parameters

  • K — the element type; ordered by compare<K>

Example

Set<int> primes = [7, 2, 5, 3];
for (var p in primes) {
    print($"{p}");   # 2, 3, 5, 7
}

Properties

Set()
