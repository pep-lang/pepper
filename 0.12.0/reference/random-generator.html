The Pepper Programming Language

Generators

Generator, a fast pseudo-random generator, and functions that use this thread's own generator, so code that only needs a random number need not pass one around.

The algorithm is xoshiro256** (Blackman and Vigna): 256 bits of state, a period of 2^256 - 1, and statistically strong output. It is not secure: anyone who sees enough output can predict the rest, so keys and tokens come from random.bytes instead.

Source: runtime/random/generator.pep

Generator

[Value] struct Generator

A seedable pseudo-random number generator (xoshiro256**).

Generator() seeds itself from the operating system, so each one gives different numbers; Generator(seed) gives the same numbers for the same seed on every platform, for reproducible tests and simulations.

A generator is a value struct: copying one copies its state, and the copy then gives the same numbers as the original. Pass it to a function that draws from it as a var you return, or keep it in a field. A generator belongs to one thread.

Example

var g = random.Generator(7);
var roll = g.next_int(1..>6);
var again = random.Generator(7);
assert(again.next_int(1..>6) == roll, "same seed, same numbers");

Makes a generator seeded with 256 bits from the operating system.

Panics

  • if the operating system cannot give random bytes, which only a broken system does

Generator()

construct(seed: ulong)

Makes a generator that always gives the same numbers for seed.

The seed is spread over the state with SplitMix64, as xoshiro's authors recommend, so nearby seeds give unrelated numbers.

Parameters

  • seed — any number; each gives its own sequence
