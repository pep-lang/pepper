The Pepper Programming Language

Unix domain sockets

Unix domain sockets: UnixListener accepts connections on a path in the file system, UnixStream is one connection, and UnixDatagram sends and receives datagrams.

They work like TcpListener, TcpStream and UdpSocket, for processes on the same machine: a path names the socket instead of an IP address and a port. Linux, macOS and Windows (10 version 1803 and later) all have the stream sockets; UnixDatagram is Linux and macOS only.

Binding creates a socket file at the path, and closing the listener does not remove it: remove it with File.remove when the server is done, and before binding again, since binding to a path that exists fails with is_address_in_use().

Source: runtime/io/unix.pep

UnixListener

[NotCopyable("owns an operating-system socket and cannot be copied")] struct UnixListener

A Unix domain socket that listens for connections on a path.

UnixListener.bind creates the socket file and listens on it; each accept() waits for the next connection and returns it as a UnixStream.

Closing: the destructor closes the socket when the last reference goes; close() closes it earlier and reports errors. Neither removes the socket file. Every operation on a closed listener fails with an error no IoError predicate identifies (EBADF on POSIX, ERROR_INVALID_HANDLE on Windows).

See also

  • UnixStream

Example

import io;

var path = io.Directory.temp().join("server.sock");
io.File.remove(path);   # left over from an earlier run
var listener = io.UnixListener.bind(path).value();
while (true) {
    var stream = listener.accept().value();
    stream.write_all("hello");
}

SharedUnixListener

[Shared] struct SharedUnixListener

A Unix domain listening socket that any thread can accept connections on: the thread-safe counterpart of UnixListener, as SharedTcpListener is of TcpListener. Each connection goes to one of the threads waiting in accept, and the stream it returns belongs to that thread.

A shared function may capture it. There is no close(), since another thread may be waiting on it: the socket closes when the last reference goes. The socket file stays.

See also

  • UnixListener

Example

import async;
import io;

main(): int {
    async.run(() => {
        var listener = io.SharedUnixListener.bind(io.Path("/tmp/server.sock")).value();
        async.spawn_on_each_worker(() => {
            while (true) {
                var accepted = listener.accept();
                if (accepted.is_err()) {
                    return;
                }
                accepted.value().write_all("hello");
            }
        });
    });
    return 0;
}

UnixStream

[NotCopyable("owns an operating-system socket and cannot be copied")] struct UnixStream

A Unix domain stream connection: a reliable, ordered stream of bytes in both directions between two processes (or threads) on this machine.

Get one from UnixStream.connect or UnixListener.accept. Reading and writing work exactly as on a TcpStream: read appends what has arrived and returns 0 once the peer has closed its side, write may send part of the data, and read_exact and write_all loop until done. Sending never raises SIGPIPE; writing to a connection the peer has closed fails with is_connection_reset() (or a broken-pipe error no predicate matches, on some systems).

Closing: the destructor closes the socket when the last reference goes; close() closes it earlier and reports errors. Every operation on a closed stream fails with an error no IoError predicate identifies.

See also

  • UnixListener

Example

import io;

var stream = io.UnixStream.connect(io.Path("/tmp/server.sock")).value();
stream.write_all("ping");
var reply = Array<u8>();
stream.read_exact(reply, 4).value();

set_read_timeout

set_read_timeout(milliseconds: ulong): IoResult<void>

Limits how long a read waits: when no data arrives for milliseconds, the read fails with is_timed_out() and the stream stays open for another try. Each wait counts on its own, so a read_exact may take longer in all. 0, the default, waits as long as it takes. It works outside a task and in one, where the task’s async.timeout can end the wait sooner.

Parameters

  • milliseconds — the longest wait, at most 4294967295 (about 49 days); 0 for none

Returns

  • an Ok result; an error with is_invalid_input() when milliseconds is too large, or an error when the stream is closed

Example

stream.set_read_timeout(5000);   # give up after 5 seconds of silence

Returns

  • the timeout in milliseconds, 0 for none

UnixDatagram

[Target(OS(Linux) || OS(Mac))] [NotCopyable("owns an operating-system socket and cannot be copied")] struct UnixDatagram

A Unix domain datagram socket (SOCK_DGRAM on AF_UNIX): like a UdpSocket for processes on the same machine, with a path in place of an address. Linux and macOS only; Windows has no Unix datagram sockets.

Each send_to delivers one whole datagram, in order, and the system never drops one silently: a send waits while the receiver’s queue is full. UnixDatagram.bind creates a socket file at a path, which closing does not remove (as for UnixListener); UnixDatagram.unbound makes a socket that can send but has no path for replies; UnixDatagram.pair makes two connected sockets.

Closing: the destructor closes the socket when the last reference goes; close() closes it earlier and reports errors. Every operation on a closed socket fails with an error no IoError predicate identifies (EBADF).

See also

  • UdpSocket
  • UnixStream

Example

import io;

var path = io.Directory.temp().join("events.sock");
io.File.remove(path);   # left over from an earlier run
var server = io.UnixDatagram.bind(path).value();
var client = io.UnixDatagram.unbound().value();
client.send_to("ping".bytes(), path);
var buffer = Array<u8>();
var (n, from) = server.receive_from(buffer, 1024).value();   # 4, an empty path

pair

static pair(): IoResult<(UnixDatagram, UnixDatagram)>

Creates two datagram sockets connected to each other, with no path (socketpair(2)): what one sends with send, the other receives. A common way to talk to a child thread or process.

Returns

  • the two sockets; an error when the system is out of descriptors, or another platform error

Example
