The Pepper Programming Language

Built-in attributes

The built-in attributes, declared as [Attribute] structs so a static block can read them like its own: field.has_attribute<Deprecated>() tests for one and function.attribute<Deprecated>().message reads its value (see the reflection chapter). The compiler acts on each attribute itself; these declarations only describe the values it records.

Source: runtime/attributes.pep

Attribute

[Attribute] struct Attribute

Marks a struct as an attribute, which can then be written above a declaration and read back in a static block.

Deprecated

[Attribute] struct Deprecated

Marks a public declaration as deprecated: each use outside a deprecated declaration warns with message.

Fields

message

const message: String

What the warning says, such as "use 'open' instead".

replacement

const replacement: String = ""

The name that replaces the declaration, offered as a fix; empty when there is none.

Alias

[Attribute] struct Alias

Gives a parameter a second permanent name that a call may use: [Alias("size", "count")] lets a call name count as size.

Fields

alias

const alias: String

The second name.

parameter

const parameter: String

The parameter it names.

Rename

[Attribute] struct Rename

Keeps a parameter's former name working behind a deprecation warning: [Rename("n", "count")].

Fields

old_name

const old_name: String

The former name.

new_name

const new_name: String

The parameter's name now.

Link

[Attribute] struct Link

Names the C library an extern links against, its C symbol, or both: [Link("m")], [Link(name = "sym")], [Link("ssl", path = "vendor")].

Fields

lib

const lib: String = ""

The library; empty when only the symbol is given.

path

const path: String = ""

A folder the linker searches for libraries, relative to the file that declares the extern unless absolute; empty for none.

name

const name: String = ""

The C symbol, when it differs from the declared name; empty otherwise.

Target

[Attribute] struct Target

Keeps a declaration only on the platforms its condition matches: [Target(OS(Linux))], [Target(!OS(Windows))].

Fields

condition

const condition: String

The condition as written, such as !OS(Windows).

BuildOption

[Attribute] struct BuildOption

Keeps a declaration only when the build defines a build option with -D: [BuildOption("USE_ZLIB")] is [Target(BuildOption(USE_ZLIB))].

Fields

name

const name: String

The build option's name, such as USE_ZLIB.

Likely

[Attribute] struct Likely

Marks the if or match arm below it as the branch usually taken, so the optimizer lays it out as the straight-line path.

Unlikely

[Attribute] struct Unlikely

Marks the if or match arm below it as a branch rarely taken, such as error handling, so the optimizer moves it out of the fast path.

NotCopyable

[Attribute] struct NotCopyable

Forbids copying a struct with copy(value), giving the reason in the error.

Fields

reason

const reason: String

Why the struct cannot be copied.

Value

[Attribute] struct Value

Makes a struct a value: stored inline and copied on assignment, with no reference count.

Equatable

[Attribute] struct Equatable

Makes a struct, or an enum whose cases carry values, compare and hash by its fields, like a tuple of them, instead of by identity: the compiler derives its == and its hash, so equal values find each other as HashMap and HashSet keys.

On a field of such a struct, it says whether the field takes part: [Equatable(exclude = true)] or [Equatable(include = false)] leaves it out of ==, the hash and the order. A field with neither takes part.

On the struct, [Equatable(ordered = true)] also derives compare from the same fields, in declaration order, as a tuple of them compares, and makes the struct Comparable, so <, sort() and Map keys use that order. Every field that takes part must be Comparable then.

Example

[Equatable(ordered = true)]
struct Version {
    var major: int;
    var minor: int;
}

Fields

include

bool include = true

On a field: whether it takes part in ==, the hash and the order; false leaves it out.

exclude

bool exclude = false

On a field: whether it is left out of ==, the hash and the order.

ordered

bool ordered = false

On the struct: whether to derive compare too, making it Comparable.

Shared

[Attribute] struct Shared

Makes a struct safe to share between threads: its counts step atomically and its fields must be const and thread-safe.

ThreadLocal

[Attribute] struct ThreadLocal

Gives a module-scope var a separate value on every thread, like C++ thread_local: each thread starts from the initializer, which must be a constant, and reads and writes only its own copy, with no locks or atomics.

The variable's type must be thread-safe (a number, a raw pointer, a [Shared] struct, a shared function type); for any other type, use async.ThreadLocal<T>. A struct value is released when a thread started with async.Thread.spawn exits; the main thread's, like every other module-scope variable, is never released.

Example

[ThreadLocal]
var calls: int = 0;

count_call() {
    calls += 1;
}

Isolated

[Attribute] struct Isolated

Makes a struct a guard that can only be the scope of a with block and never escapes it.

Implicit

[Attribute] struct Implicit

Lets a one-parameter constructor convert implicitly wherever a value of its parameter's type flows into the struct's type.

Move

[Attribute] struct Move

Marks a parameter that takes its argument's reference: the caller's variable may not be used again.

MoveSource

[Attribute] struct MoveSource

Marks the parameter of a function that moves a value out of its source, as move does.

Locked

[Attribute] struct Locked

Marks a function-typed parameter that is called while a lock is held, so it may use the locked value.

Unsafe

[Attribute] struct Unsafe

Removes runtime checks from one function's body, as --no-runtime-checks removes them from a whole build: [Unsafe("overflow")], [Unsafe("overflow,bounds")] or [Unsafe("all")]. It applies at every optimization level. Calls the function makes keep their own checks, except the index check that an Array or String method makes for its caller, which bounds removes too. Removing bounds or null gives up memory safety in that function.

Fields

checks

const checks: String

The checks to remove, comma-separated: overflow, divide, shift, bounds, null, or all.

Cold

[Attribute] struct Cold

Marks a function rarely called, such as an allocator's slow path or error handling, so the optimizer never inlines it and its callers' fast paths stay small enough to inline themselves.

Test

[Attribute] struct Test

Marks a function as a unit test: pep-test (pepper test) builds it into a test program and runs it in a child process of its own. The function takes no parameters and returns nothing; it passes when it returns and fails when it panics (see expect_equal). A build without --test leaves [Test] functions out.

ShouldPanic

[Attribute] struct ShouldPanic

Marks a [Test] function as one that passes only when it panics: [ShouldPanic] takes any panic, and [ShouldPanic("index out of range")] only a panic whose message contains that text.

Fields

message

const message: String = ""

Text the panic's message must contain; empty for any panic.

Export

[Attribute] struct Export

Makes a free function callable from C, in a library built with --lib static or --lib shared: [Export], or [Export(name = "c_name")] for a C symbol other than its name.

Fields

name

const name: String = ""

The C symbol, when it differs from the function's name; empty otherwise.

__BuiltIn

[Attribute] struct __BuiltIn

Declares a compiler built-in in the runtime, for the reference and the editor: the compiler ignores the declaration, whose functions end in ;. [__BuiltIn("reflect.name")] names the built-in when it is not the declaration's own name. Only the runtime may use it.

Fields

name

const name: String = ""

The built-in's name, when it differs from the declaration's; empty otherwise.

__Sealed

[Attribute] struct __Sealed

Seals a trait: only the runtime declares which types conform to it, and an extend T with Trait outside the runtime is an error at the trait's name. Errors about a type that does not conform name no extend to add. The SIMD lane traits are sealed, as a Vector holds only the number types. Only the runtime may use it.
