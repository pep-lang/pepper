The Pepper Programming Language

tls/stream.pep

TLS connections: TlsConnector opens client connections, TlsAcceptor accepts server connections, and TlsStream is one encrypted connection over a TcpStream.

Source: runtime/tls/stream.pep

TlsConnector

[Shared] struct TlsConnector

Opens TLS client connections, checking each server’s certificate.

A connector trusts the system’s root certificates; add_root_certificate trusts more, such as a test certificate authority. Each connect runs the TLS handshake over a connected TcpStream and checks that the server’s certificate is valid and issued for the host name given. Only TLS 1.2 and 1.3 are offered.

A connector is [Shared]: make one and use it from every thread and task. Configure it (add_root_certificate) before the first connect.

See also

  • TlsStream

Example

    import tls;

    var connector = tls.TlsConnector.create().value();
    var stream = connector.connect_host("localhost", 8443).value();
    stream.write_all("ping");

connect

connect(stream: io.TcpStream, host: String): io.IoResult<TlsStream>

Runs the TLS handshake as the client over stream and checks the server’s certificate.

Parameters

  • stream — a connected TCP stream; the TlsStream keeps it, and nothing else should read or write it afterwards
  • host — the name the certificate must be for, also sent to the server as the requested name (SNI); an IP address is checked against the certificate’s addresses instead

Returns

  • the encrypted stream; an error when the handshake fails or the certificate is not trusted (“certificate verify failed: …”), or an io error from the socket

Connects to host on port with TcpStream.connect_host, then runs the handshake as connect does.

Parameters

  • host — a host name or an IP address
  • port — the port, usually 443

Returns

  • the encrypted stream; the errors of TcpStream.connect_host and of connect

TlsAcceptor

[Shared] struct TlsAcceptor

Accepts TLS server connections with one certificate.

An acceptor presents a certificate chain and its private key, read from PEM files. Each accept runs the TLS handshake over a TcpStream that a TcpListener accepted. Clients are not asked for certificates.

An acceptor is [Shared], so the accept loops of every worker can share one.

See also

  • TlsStream

Example

    import io;
    import tls;

    var acceptor = tls.TlsAcceptor.create(io.Path("cert.pem"), io.Path("key.pem")).value();
    var listener = io.TcpListener.bind(io.SocketAddress.parse("0.0.0.0:8443").value()).value();
    while (true) {
        var (tcp, peer) = listener.accept().value();
        var accepted = acceptor.accept(tcp);
        if (accepted.is_ok()) {
            accepted.value().write_all("hello over TLS");
        }
    }

TlsStream

[NotCopyable("owns a TLS connection and cannot be copied")] struct TlsStream

An encrypted connection: TLS over a TcpStream.

Get one from TlsConnector.connect or TlsAcceptor.accept. Reading and writing work as on a TcpStream, on the decrypted bytes: read appends what has arrived and returns 0 once the peer has closed the connection, write may send part of the data, and read_exact and write_all loop until done. In a task, a call that has to wait parks only the task.

shutdown() tells the peer that nothing more is coming (a TLS close_notify). A peer that closes the TCP connection without one also ends the stream: read returns 0.

Closing: the destructor closes the connection when the last reference goes; close() closes it earlier. Neither sends close_notify; call shutdown() first for that.

See also

  • TlsConnector
  • TlsAcceptor

Example

    var stream = connector.connect_host("localhost", 8443).value();
    stream.write_all("ping");
    var reply = Array<u8>();
    while (stream.read(reply, 4096).value() > 0) {
    }

read

read(buffer: u8[], max: ulong): io.IoResult<ulong>

Waits until data arrives, then appends up to max decrypted bytes of it to buffer.

Parameters

  • buffer — the array the bytes are appended to
  • max — the most bytes to read; 0 reads nothing and returns 0

Returns

  • the number of bytes appended, 0 once the peer has closed the connection; an error when the stream is closed, a TLS error, or an io error from the socket

read_exact

read_exact(buffer: u8[], count: ulong): io.IoResult<void>

Reads until exactly count more bytes are appended to buffer.

Parameters

  • buffer — the array the bytes are appended to
  • count — the number of bytes to read

Returns

  • an Ok result once count bytes are appended; an error when the connection ends first, or an error as for read. The bytes read before an error stay in buffer.

shutdown

shutdown(): io.IoResult<void>

Tells the peer that nothing more is coming (sends a TLS close_notify). The peer’s reads return 0 after the data sent before.

Returns

  • an Ok result on success; an error when the stream is closed, or an io error from the socket

close

close(): io.IoResult<void>

Closes the connection now, without a close_notify (see shutdown). Closing a closed stream does nothing.

Returns

  • an Ok result on success or when already closed; the platform error when closing the socket fails
