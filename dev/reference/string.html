The Pepper Programming Language

String

Source: runtime/string.pep

String

struct String

A mutable, reference-counted string of UTF-8 text. A string literal ("text") is a String wherever a String is expected; its own type is StringConstant.

Two measures describe a String, and each API says which one it uses:

  • Code points (Unicode characters): length, is_empty, the indexer s[i], substr, and iteration.
  • Bytes of UTF-8: size, find, starts_with, and ends_with. The byte size is the authoritative length, so the data may contain NUL bytes. It is never derived from a terminator.

A String's bytes are not guaranteed to be followed by a NUL. Only c_str() guarantees one, so call it to hand the text to C; anything else that reads the bytes must stop at size.

A String is a reference type: var b = a; shares one object, so append, +=, and grow are visible through every reference. Use copy() or + for an independent copy. Equality (==) compares content.

A StringIterator panics when the String has been changed by append, +=, or grow since the iterator was created, so modifying a String while a for loop iterates it panics.

To build text from values, use an interpolated string ($"{name}: {count:>4}") or String.format("{0}: {1:>4}", name, count), a compiler intrinsic whose braces name its arguments by position (see the String interpolation chapter).

Example

var s = "héllo";
assert(s.length == 5, "5 code points");
assert(s.size == 6, "6 bytes: 'é' is 2");
s.append(" world");
assert(s.find("world") == 7, "find returns a byte offset");
assert(s[1] == "é", "the indexer counts code points");
for (var c in s) {
    print(c);   # one code point per line
}

Constructor

String()

construct(data: __ptr<char> = __null, size: ulong = 0, length: ulong = 0)

Creates a String by copying size bytes of data into a new NUL-terminated buffer. With no arguments, it creates an empty String with no buffer; its c_str() is still a valid empty C string.

When data is not __null and size is 0, data is treated as a NUL-terminated C string:

  • with length nonzero, size becomes the byte length of its first length code points (0 if the C string is not valid UTF-8);
  • with length 0, size becomes the C string's whole byte length.

When length is 0, it is counted from the bytes. A nonzero length is trusted, not checked against the data. Runs in O(size).

Parameters

  • data — the bytes to copy; __null for an empty String (then pass no sizes, because they are stored as given)
  • size — the number of bytes to copy from data; 0 treats data as a NUL-terminated C string
  • length — the number of code points in those bytes

Example

var empty = String();
var s = "abc";
var copy = String(s.c_str(), s.size, s.length);

grow

grow(new_size: ulong)

Extends the byte buffer to new_size bytes and fills the new bytes with zeros. Does nothing when new_size is not greater than size.

A low-level primitive for append. It updates size but not length, so the zero bytes it adds are not counted as code points until the caller overwrites them and fixes the length. When it grows the buffer, it invalidates running iterators and may reallocate the buffer, which invalidates pointers from c_str(). Runs in O(new_size).

Parameters

  • new_size — the new byte length

append

append(rhs: String)

Appends the content of rhs to this String in place, updating size and length.

Always invalidates running iterators, even when rhs is empty, so appending during iteration panics. It may reallocate the buffer. Every reference to this String sees the change. Runs in O(size + rhs.size).

Parameters

  • rhs — the String to append; it is not modified

Example

var s = "TEST";
s.append("ING");   # s == "TESTING"

operator []

[](idx: int): String

Returns the code point at code-point index idx as a new one-code-point String.

A negative idx counts from the end (s[-1] is the last code point). length is added until the index is non-negative, so any negative index wraps, and s[-7] of a 3-code-point String is s[2]. Runs in O(idx) because it walks the UTF-8 bytes. Use for (var c in s) to visit every code point in O(size).

Parameters

  • idx — the code-point index; negative counts from the end

Returns

  • a new String that holds the one code point

Panics

  • if idx is not less than length after the negative index is normalized, which includes any index into an empty String

Example

var s = "TEST";
assert(s[0] == "T", "first");
assert(s[-1] == "T", "last");

iterate

iterate(): StringIterator

Returns an iterator over the String's code points, which makes String Iterable<String>: for (var c in s) visits each code point as a one-code-point String, the same value s[i] gives.

The iterator holds a reference to this String. The whole loop runs in O(size). Modifying the String during iteration makes the iterator panic.

Returns

  • a new iterator, positioned before the first code point

Example

var n = 0;
for (var c in "héllo") {
    n = n + 1;   # 5 iterations
}

c_str

c_str(): __ptr<char>

Returns the String's buffer as a NUL-terminated C string.

This is the one API that guarantees a NUL after the content: a String is not otherwise guaranteed to be NUL-terminated, so code that needs the terminator calls c_str() rather than relying on the buffer.

The pointer is owned by the String. It is valid until the String is destroyed or append, +=, or grow reallocates it. It is never __null: a String built with no data (String()) returns a constant empty C string, so it can go to C as it is. C functions stop at the first NUL byte in the content.

Returns

  • the String's NUL-terminated byte buffer

copy

copy(): String

Returns a new String with the same content and its own buffer, so later changes to either String do not affect the other. Runs in O(size).

This is also how copy(value) copies a String (the Copyable<String> implementation).

Returns

  • an independent copy of this String

Example

var a = "abc";
var b = a.copy();
b.append("d");   # a is still "abc"

find

find(needle: String, from: ulong = 0): long

Returns the byte offset of the first occurrence of needle, or -1 when it does not occur.

The offset counts bytes, not code points. To use it with s[i] or substr, convert it with String.length_of(s.c_str(), offset). An empty needle is found at 0 unless this String is empty, in which case the result is -1. The result is also -1 when needle is not valid UTF-8, or when this String holds invalid UTF-8 before the first match. Bytes past the match are not checked, so searching on from each match (as split and replace do) reads the String once in all. The search is the C library's memmem, which compares many bytes per step (Windows, which has none, jumps between matches of the first byte with memchr).

With from, the search starts at that byte offset, which must be a code point boundary (an offset find returned, plus a match's size, is one); an offset past the end, or inside a code point, finds nothing. The result still counts from the start of the String.

Parameters

  • needle — the text to search for
  • from — the byte offset to start searching at; 0 by default

Returns

  • the byte offset of the first match at or after from, or -1 when there is none

Example

var s = "TESTING";
assert(s.find("STI") == 2, "byte offset");
assert(s.find("xyz") == -1, "absent");
assert("a,b,c".find(",", 2) == 3, "the second comma");

split

split(separator: String): String[]

Splits the String at every occurrence of separator and returns the pieces between them, in order. Adjacent separators give an empty piece, and so does a separator at either end: "a,,b".split(",") is ["a", "", "b"] and ",a".split(",") is ["", "a"]. A String without separator, the empty String included, gives one piece: the whole String. Runs in O(size * separator.size).

Parameters

  • separator — the text to split at

Returns

  • a new Array with one new String per piece

Panics

  • if separator is empty

Example

var parts = "a,b,,c".split(",");
assert(parts.count == 4, "four pieces");
assert(parts[2] == "", "an empty piece");

split_once

split_once(separator: String): (String, String)?

Splits the String at the first occurrence of separator: the text before it and the text after it, or none when it does not occur. Runs in O(size * separator.size).

Parameters

  • separator — the text to split at

Returns

  • the pieces before and after the first separator, or none

Panics

Example

lines

lines(): String[]

Splits the String into lines and returns them without their line endings. A line ends at "\n" or "\r\n". A final line with no ending is included, but the end of the String after a final line ending does not start another line, so "a\nb\n" and "a\nb" both give ["a", "b"], and "" gives no lines. Runs in O(size).

Returns

  • a new Array with one new String per line

Example

var lines = "first\r\nsecond\n\nfourth".lines();
assert(lines.count == 4, "four lines");
assert(lines[1] == "second", "\\r\\n removed");
assert(lines[2] == "", "an empty line");

StringConstant

[Value] struct StringConstant

The text of a string literal: a pointer to its bytes, which never change and are never freed, with their byte size and code-point length. A string literal's type is StringConstant, and so is a const with no written type initialized from one (const NAME = "pepper";); where a String is expected, the literal is a String (see the Strings chapter of the book).

A StringConstant is a [Value] type: copying one copies the pointer and steps no reference count, and any thread may read it. Its bytes always end in a NUL byte, so c_str() goes to C as it is. It has String's read API, measured the same way (length in code points, size and offsets in bytes); the methods that make new text return a String. A StringConstant converts to a String wherever a String is expected, as if String had an [Implicit] constructor from it: the conversion, like String(text), copies the bytes. Where C expects a char*, it passes its own bytes, as c_str() does.

Unlike a String, a StringConstant may hold bytes that are not UTF-8: a literal's \x80 to \xFF escapes write raw bytes, so a static byte table can be a string constant. Read such bytes with size and byte_at; length is 0 for them, and the code-point API (the indexer, iteration) and a conversion to String need UTF-8.

Example

StringConstant name = "pepper";
assert(name.length == 6, "6 code points");
assert(name.starts_with("pep"), "the read API of String");
String copy = name;   # a new String with its own bytes
copy.append("!");

to_string

to_string(value: double): String

Returns the shortest decimal text that reads back as exactly value, as Swift prints a Double.

A whole number keeps a .0 ("3.0"), so the text always reads as a floating-point number. Values from 1e-4 up to 1e16 print in decimal; others use an exponent ("1e+16", "1.5e-05"). The special values are "nan", "inf" and "-inf". For a fixed number of fraction digits, interpolate with a precision instead: $"{value:.2}".

The digits come from the Ryu algorithm, which takes a fixed, small number of steps per value.

Parameters

  • value — the number to convert

Returns

  • a new String such as "0.1" or "-2.5"

Example

assert(to_string(0.1) == "0.1", "shortest");
assert(to_string(3.0) == "3.0", "keeps the point");
assert(to_string(1.0e20) == "1e+20", "exponent");

print

print(text: String)

Writes text and a line break to standard output.

Any other value prints through print(value), which writes its to_string text. To combine values, interpolate them (print($"total: {n}")), or pass a format string and arguments, which prints what String.format makes of them (print("{0} of {1}", a, b)). A string with no arguments after it is printed as written, braces included.

Each line is flushed as it is printed, as Rust's println! does, so the output appears as the program runs even when standard output is a pipe or a file (where C would buffer it until the program exits).

Parameters

  • text — the text to print

Example

print("hello");
var n = 3;
print($"n = {n}");
print("{0} + {1} = {2}", 1, 2, 1 + 2);   # 1 + 2 = 3

print

print<T>(value: T)

Writes the text of value and a line break to standard output: what $"{value}" would make of it, through to_string. That covers numbers, bool (true or false), tuples, and any type with a to_string() method or a to_string<T> override; another type is a compile error at the argument.

Type parameters

  • T — the type of value

Parameters

  • value — the value to print

Example

print(42);          # 42
print(0.5);         # 0.5
print((1, "two"));  # (1, two)

to_string

to_string<T>(value: T): String

Returns the text of value by calling its to_string() method: the overload for any type that is ToString.

Declare a concrete override for a type that has no to_string() method of its own, or whose interpolated text should differ from it; like hash<Point>, an override is used by the whole program, including interpolated strings.

Type parameters

  • T — the type of value; it must have a to_string() method unless an override to_string<T> exists

Parameters

  • value — the value to convert

Returns

  • the String that value.to_string() returns

Example

struct Point {
    var x: int = 0;
    var y: int = 0;
    construct(this.x = 0, this.y = 0) {}
}

to_string<Point>(value: Point): String {
    var x = value.x;
    var y = value.y;
    return $"({x}, {y})";
}

ToString

trait ToString

Something with a text form: a to_string() method returning a String.

An interpolated string ($"total: {a + b}") converts each value it holds with to_string(value), so a struct that implements ToString can be interpolated, as can the integers, bool, and String, which have to_string overloads. String, StringBuilder and io.Path implement it.

Example

struct Point {
    var x: int = 0;
    var y: int = 0;
    construct(this.x = 0, this.y = 0) {}
}

extend Point with ToString {
    to_string(): String {
        return $"({x}, {y})";
    }
}

var p = Point(1, 2);
assert($"p = {p}" == "p = (1, 2)", "interpolated");

StringBuilder

struct StringBuilder

Builds a String from many pieces without copying the text built so far on every append.

String.append grows its buffer to the exact new size, so a long run of appends can copy the text repeatedly. A StringBuilder doubles its buffer when it is full, so appending is amortized O(piece size). Call to_string() for the result; the builder can keep appending afterward.

Example

var out = StringBuilder();
out.append("line ").append(to_string(3)).append("\n");
var text = out.to_string();   # "line 3\n"

StringIterator

[Value] struct StringIterator

An Iterator<String> over a String's code points, returned by String.iterate() and used by for (var c in s).

Call next() to advance, then current() for the code point it moved to. Both methods panic if the String has been modified since the iterator was created. Create it with String.iterate(): a default-constructed StringIterator() has no String to walk.

Example

var it = "ab".iterate();
while (it.next()) {
    print(it.current());   # "a", then "b"
}

next(): bool

Advances to the next code point. Runs in O(1) per code point.

Returns false once it passes the end, and on every call after that. A malformed UTF-8 sequence is yielded, together with the rest of the bytes, as one final "code point".
