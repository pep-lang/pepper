The Pepper Programming Language

Backtraces

Capturing the call stack (capture, Backtrace) and resolving it to functions and source lines (StackFrame).

Capturing only records return addresses, so it is cheap enough to do whenever something might need reporting later. The addresses are resolved, from the program's symbol table and its debug info, only when Backtrace.frames() or to_string() asks for them.

A function name needs the program's symbol table, which every build keeps unless the executable is stripped. A file, line and column need the debug info a -g build carries:

  • Linux: the executable's ELF symbol table and DWARF line table.
  • macOS: the executable's symbol table, and the DWARF line table of the .dSYM bundle a -g build writes beside it.
  • Windows: DbgHelp, which reads the .pdb every build writes beside the executable: function names only, or with -g source lines too (no columns).
  • WASI: a WebAssembly program cannot walk its stack, so a backtrace is empty.

A function the optimizer inlined into its caller has no frame of its own, so each address is expanded into its chain of inlined calls, from the debug info of a -g build: one StackFrame per call, marked inlined.

Frames inside the runtime's own capture and panic code are left out, and so are the runtime's operator methods (Array<int>.__index_get, what a[i] calls) between a panic and the code that caused it, and the C runtime's frames below main. frames(full = true), or PEPPER_BACKTRACE=full for a panic's backtrace, keeps them all.

Source: runtime/debug/backtrace.pep

StackFrame

struct StackFrame

One call on the stack: where it returns to, and the function and source position that address belongs to.

A call the optimizer inlined is a frame too, with inlined set: it shares its address with the frames of its callers, up to the first frame that is not inlined, which is the real one.

Example

import debug;

main(): int {
    var frame = debug.capture().frames()[0];
    assert(frame.function == "main", "the innermost frame is main");
    print(frame.to_string());   # main at main.pep:4:21 in a -g build
    return 0;
}

Fields

address

var address: ulong

The return address: the instruction the call returns to.

function

var function: String

The function's name, such as main or Point.length; empty when the program has no symbol for the address.

file

var file: String

The source file, as it was named to the compiler; empty without debug info.

line

var line: int

The 1-based source line of the call; 0 without debug info.

column

var column: int

The 1-based source column of the call; 0 when unknown.

inlined

var inlined: bool

Whether the optimizer inlined this call into its caller, the next frame: the function has no frame of its own on the stack.

Constructor

StackFrame()

construct(address: ulong = 0)

Creates a StackFrame for address, with no function or source position yet.

Parameters

  • address — the return address

Methods

to_string

to_string(): String

Returns the frame as text: function at file:line:column, with the parts that are unknown left out, the address in hexadecimal when the function is unknown, and (inlined) after an inlined call.

Returns

  • the frame as text

Backtrace

struct Backtrace

The call stack at the point capture() ran, as return addresses, innermost first.

Example

import debug;

main(): int {
    var trace = debug.capture();
    for (var frame in trace.frames()) {
        print(frame.to_string());
    }
    return 0;
}

Fields

addresses

var addresses: Array<ulong>

The return address of each call, innermost first, as captured: it includes the frames of capture itself, which frames() leaves out.

Constructor

Backtrace()

construct()

Creates an empty Backtrace. Use capture() to record the stack.

Methods

frames

frames(full: bool = false): Array<StackFrame>

Resolves each return address to its function and source position. Runs in time proportional to the program's symbol table and debug info, which it reads each call.

In a -g build, an address inside code the optimizer inlined becomes a frame for each inlined call, innermost first, each marked inlined, followed by the real frame (Linux and macOS read the DWARF, Windows asks DbgHelp).

Unless full, leaves out, at the top, the frames of capture and of the runtime's panic code and the runtime's operator methods (Array<int>.__index_get for a[i]) a panic came through; and at the bottom, the C runtime's frames below main.

Parameters

  • full — whether to keep every frame

Returns

  • the frames, innermost first

to_string

to_string(): String

Returns the frames as text, one per line, each numbered and indented ( 0: main at main.pep:4:5), with a newline after the last.

Returns

  • the frames as text

capture

capture(): Backtrace

Records the call stack: the return address of every call that led here. Cheap: the addresses are resolved only when Backtrace.frames() or to_string() asks for them.

Records at most 128 calls, the innermost ones. On WASI the Backtrace is empty.

Returns

  • the stack, innermost call first

Example

import debug;

main(): int {
    var trace = debug.capture();
    print(trace.to_string());
    return 0;
}

print_backtrace

print_backtrace()

Writes the current call stack to standard error, a line per frame, after a backtrace: line: what a panic prints after its message.

A panic prints it in a build without -O. Set the PEPPER_BACKTRACE environment variable to 1 to print it in an optimized build too, to full to also print the runtime frames it leaves out (see Backtrace.frames), or to 0 to never print it.

Example

import debug;

main(): int {
    debug.print_backtrace();
    return 0;
}
