The Pepper Programming Language

File

Source: runtime/io/file.pep

OpenOptions

struct OpenOptions

Describes how File.open_with (or OpenOptions.open) opens a file: which access it asks for, and whether the file is created or truncated.

A builder in the style of Rust’s std::fs::OpenOptions. A new OpenOptions has every option off; each setter stores its flag and returns this same OpenOptions, so calls chain. The rules, checked when the file is opened:

  • At least one of read, write or append must be set, or opening fails with is_invalid_input().
  • create, create_new and truncate need write or append, or opening fails with is_invalid_input().
  • append implies write access, and every write goes to the current end of the file whatever the position; it wins over write.
  • create opens an existing file as it is (combine with truncate to empty it) and creates a missing one.
  • create_new creates the file and fails with is_already_exists() when it already exists, atomically (O_EXCL on POSIX, CREATE_NEW on Windows); create is then irrelevant.
  • truncate empties an existing file on open.
  • Without create or create_new, a missing file fails with is_not_found().

On POSIX a created file gets mode 0666 less the process umask, and the descriptor is opened close-on-exec. On Windows every file is opened sharing read, write and delete access with other openers.

See also

  • File.open_with

Example

    var r = OpenOptions().read(true).write(true).create(true).open(Path("data.bin"));
    if (r.is_err()) {
        return 1;
    }
    var f = r.value();

FileType

enum FileType

The kind of a file system object, as Metadata.file_type and DirEntry.file_type report it.

A symlink is reported as Symlink only where links are not followed (Path.symlink_metadata() and directory listings); on Windows that is any reparse point, junctions included, even one that points to a directory.

See also

  • Metadata

Example

    import io;

    var m = io.Path("notes.txt").metadata();
    if (m.is_ok()) {
        match (m.value().file_type) {
            File => { print("a file"); }
            Directory => { print("a directory"); }
            Symlink, Other => { print("something else"); }
        }
    }

Metadata

struct Metadata

Describes a file system object: its kind, size, read-only flag, permission bits and timestamps, as a snapshot taken when it was queried.

Returned by File.metadata(), Path.metadata() (which follows symlinks), Path.symlink_metadata() (which does not) and DirEntry.metadata(). The timestamps are nanoseconds since the Unix epoch (1970-01-01 00:00:00 UTC). On POSIX the metadata comes from statx (Linux) or stat (macOS); on Windows from GetFileInformationByHandle.

Example

    var m = Path("notes.txt").metadata();
    if (m.is_ok() && m.value().is_file) {
        var bytes = m.value().size;
    }

Fields

size

ulong size

The file’s length in bytes.

file_type

FileType file_type

The kind of object: File, Directory, Symlink or Other. It agrees with is_file, is_directory and is_symlink, except that a Windows reparse point to a directory is Symlink with both is_directory and is_symlink set.

is_file

bool is_file

Whether this is a regular file. On Windows, anything that is neither a directory nor a reparse point (symlink) counts as a file.

is_directory

bool is_directory

Whether this is a directory.

is_symlink

bool is_symlink

Whether this is a symbolic link itself. Only metadata that does not follow links (Path.symlink_metadata()) can report one. On Windows this is any reparse point (FILE_ATTRIBUTE_REPARSE_POINT), which includes junctions.

read_only

bool read_only

Whether the file is read-only: on POSIX, no write permission bit (0222) is set for anyone; on Windows, FILE_ATTRIBUTE_READONLY is set.

modified

long modified

The time of the last modification of the contents, in nanoseconds since the Unix epoch.

accessed

long accessed

The time of the last access, in nanoseconds since the Unix epoch (file systems mounted with noatime or relatime update it rarely or never).

created

long? created

The creation (birth) time, in nanoseconds since the Unix epoch; none where the platform does not report one, such as on Linux file systems that do not record it.

permissions

Mode permissions

The raw permission bits: on POSIX the mode_t permission bits (mode & 07777, for example 256 for owner read); on Windows the FILE_ATTRIBUTE_* bits.

Creates a Metadata with every number zero, every flag false, file_type Other and created none. Metadata is normally obtained from a query such as File.metadata().

File

[NotCopyable( "owns an operating-system handle and cannot be copied; send its path, and open the file again on the receiving thread" )] struct File

An open file, or a standard stream, read and written through its platform handle (a file descriptor on POSIX, a HANDLE on Windows).

Open one with File.open (read-only), File.create (write-only, created or truncated), or File.open_with / OpenOptions.open for anything else. The static conveniences read_bytes, read_to_string, write_bytes, write_text, copy, rename and remove work on a whole file by path.

I/O is unbuffered: each read and write is one system call. Reads and writes start at the current position and move it forward; the seek_* methods move it explicitly. A write to a standard stream first flushes the output print has buffered, so the two never come out of order.

Closing: the File’s destructor closes an owned handle when the last reference to the File is released, and ignores any error. Call close() to close earlier or to observe the error. The standard streams (stdin(), stdout(), stderr()) are never closed by a File. Every operation on a closed File fails with an error that none of the IoError predicates identify (EBADF on POSIX, ERROR_INVALID_HANDLE on Windows).

Errors are IoError values carrying the platform’s code; use its predicates (is_not_found(), is_permission_denied(), …) to tell kinds apart portably.

Example

    var f = File.create(Path("out.txt")).value();
    f.write_all("hello");
    f.close();
    var text = File.read_to_string(Path("out.txt")).value();   # "hello"

Fields

path

Path path

The path the File was opened with; <stdin>, <stdout> or <stderr> for a standard stream, and empty for a File() never opened.

Constructor

File()

construct()

Creates a closed File that owns nothing yet: is_open() is false and every I/O method fails. Use File.open, File.create or File.open_with to get an open one.

create

static create(path: Path): IoResult<File>

Opens a file for writing only, creating it if it is missing and truncating it to 0 bytes if it exists.

On POSIX a created file gets mode 0666 less the process umask.

Parameters

  • path — the file to create or truncate

Returns

  • the open File, empty and positioned at 0; an error with is_not_found() when the path is empty or its parent directory does not exist, is_permission_denied() when access is refused, or another platform error (on POSIX, is_is_a_directory() when the path is a directory)

Example

    f.write_all("done");

open_with

static open_with(path: Path, options: OpenOptions): IoResult<File>

Opens path as options describe. OpenOptions.open is the same call written as a builder.

The options are checked first, as in Rust: at least one of read, write or append is required, and create, create_new or truncate require write or append. The position starts at 0 (append mode still writes at the end).

Parameters

  • path — the file to open
  • options — the access mode and creation behavior

Returns

  • the open File; an error with is_invalid_input() when no access mode is set or create, create_new or truncate is set without write or append; is_not_found() when the path is empty, or the file (or a parent directory) is missing and neither create nor create_new is set; is_already_exists() when create_new is set and the path exists; is_permission_denied() when access is refused; or another platform error

Example

    var opts = OpenOptions().write(true).create_new(true);
    var r = File.open_with(Path("lock"), opts);
    if (r.is_err() && r.error().is_already_exists()) {
        return 1;
    }

std_file

static std_file(stream: StdStream, name: String): File

Returns a File for one of the process’s standard streams. The File does not own the handle, so neither close() nor the destructor closes the stream. stdin(), stdout() and stderr() are the usual way to call this.

On Windows a process without a console or redirection may get a null handle, and the File is then not open.

Parameters

  • stream — the stream
  • name — the display name stored in the File’s path, such as <stdout>

Returns

  • a File on that stream, that does not close the stream when released

Example

    var err = File.std_file(StdStream.Error, "<stderr>");
    err.write_all("warning");

copy

static copy(from: Path, to: Path): IoResult<ulong>

Copies the contents of the file from to to, creating to or truncating it first, in 64 KiB chunks.

Only the contents are copied: to keeps its own permissions and timestamps (a new file gets the defaults of File.create). A failure part way leaves to partly written.

Parameters

  • from — the file to copy
  • to — the destination file

Returns

  • the number of bytes copied; is_invalid_input() when from and to are the same file (after resolving symlinks), which truncating to would empty before it was read; otherwise an error as for File.open on from (such as is_not_found()), File.create on to, or a read, write or close failure

Example

    var n = File.copy(Path("a.txt"), Path("b.txt")).value();

rename

static rename(from: Path, to: Path): IoResult<void>

Renames or moves from to to, replacing an existing file at to (rename on POSIX, MoveFileExW with MOVEFILE_REPLACE_EXISTING on Windows).

Works for directories too. Moving between file systems (volumes) fails rather than copying.

Parameters

  • from — the existing path
  • to — the new path

Returns

  • an Ok result on success; an error with is_not_found() when from (or the parent of to) does not exist or, on POSIX, either path is empty, is_permission_denied() when access is refused, or another platform error

Example

    File.rename(Path("draft.txt"), Path("final.txt"));

remove

static remove(path: Path): IoResult<void>

Deletes the file at path. A symlink is removed itself, not its target. Directories are not removed: use Directory.remove or Directory.remove_all.

Parameters

  • path — the file to delete

Returns

  • an Ok result on success; an error with is_not_found() when the path does not exist (on POSIX, also when it is empty); when it is a directory, is_is_a_directory() on Linux and is_permission_denied() on macOS and Windows; is_permission_denied() when access is refused (on Windows also for a read-only file); or another platform error

Example

read

read(buffer: u8[], max: ulong): IoResult<ulong>

Reads up to max bytes from the current position and appends them to buf, growing it; the bytes already in buf are kept. Advances the position by the count read.

One system call: the read may be partial, returning fewer than max bytes before the end of the file (always so for pipes and terminals), and a single call moves at most about 2 GiB on POSIX or 1 GiB on Windows. Loop until it returns 0 to read everything, or use read_all. On POSIX an interrupted read (EINTR) is retried. On failure buffer keeps its previous contents.

Parameters

  • buffer — the array the bytes are appended to
  • max — the most bytes to read; 0 reads nothing and returns 0

Returns

  • the number of bytes appended, 0 at end of file; an error when the File is closed, or is_is_a_directory() when it is a directory, or another platform error

Example

    var buf = Array<u8>();
    while (true) {
        var r = f.read(buf, 4096);
        if (r.is_err() || r.value() == 0) {
            break;
        }
    }

read_all

read_all(): IoResult<u8[]>

Reads everything from the current position to the end of the file, in 64 KiB chunks, leaving the position at the end.

Returns

  • a new array of the bytes read (empty at end of file); an error when the File is closed, is_is_a_directory() when it is a directory, or another platform error, in which case the bytes read so far are discarded

read_string

read_string(): IoResult<String>

Reads everything from the current position to the end of the file, as read_all does, and returns it as UTF-8 text.

The bytes must be strictly valid UTF-8 (RFC 3629: no overlong forms, surrogates, or code points past U+10FFFF). A byte-order mark is kept as part of the text.

Returns

  • the text read (empty at end of file); an error with is_invalid_input() when the bytes are not valid UTF-8, or any error read_all returns

write

write(data: u8[]): IoResult<ulong>

Writes bytes from data at the current position (or at the end, in append mode) with a single system call, and advances the position.

The write may be partial: it can write fewer than data.count bytes, and one call moves at most about 2 GiB on POSIX or 1 GiB on Windows. Use write_all to write everything. On POSIX an interrupted write (EINTR) is retried.

Parameters

  • data — the bytes to write

Returns

  • the number of bytes written, which may be less than data.count; an error when the File is closed or was not opened for writing, or another platform error

write_all

seek

seek(from: SeekFrom): IoResult<Offset>

Moves the position as from says: to an offset from the start, from the current position, or from the end of the file.

Seeking past the end is allowed; a later write there fills the gap with zeros. A position before the start of the file is an error. Seeking a stream that has no position (a pipe or a terminal) fails on POSIX and has platform-defined results on Windows.

Parameters

  • from — the origin and the offset from it

Returns

  • the new position, in bytes from the start of the file; an error when the File is closed, the resulting position would be negative (on POSIX, with is_invalid_input()), or the stream cannot seek

Example

    var f = File.open(Path("data.bin")).value();
    var length = f.seek(SeekFrom.End(0)).value();
    f.seek(SeekFrom.Start(0));

close(): IoResult<void>

Closes the File now, to observe the error the system reports (for example a deferred write failure). Without it the destructor closes the handle and ignores errors.

Idempotent: closing a closed File succeeds. The File counts as closed afterwards even when closing reports an error, so the handle is never closed twice. A standard stream is only marked closed: the stream stays open, and File.stdout() and the like still work.

Returns

  • an Ok result on success or when already closed; the platform error when closing an owned handle fails

Example

    var f = File.create(Path("out.bin")).value();
    f.write_all("data");
    if (f.close().is_err()) {
        return 1;
    }
