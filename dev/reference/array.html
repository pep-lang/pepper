Array

[__Lazy] struct Array<T>

A growable, contiguous, zero-indexed sequence of T values.

Elements live in one heap buffer that doubles when full (starting at 4 slots), so append is amortized O(1) and indexing is O(1). When T is a struct type, each slot holds a counted reference, exactly like a std::vector<std::shared_ptr<T>>: storing an element acquires it, overwriting or removing one releases the old occupant, and destroying the Array releases every element it still holds. Moving elements within the Array (insert, remove_at, swap, reverse) does not change their reference counts.

Array is itself a struct, so assigning it or passing it to a function shares the same Array rather than copying its elements; use clone() for an independent copy.

An empty Array allocates nothing: Array<T>() makes no object until the Array is first written (append, insert, reserve, ...) or shared (assigned, stored, passed or returned), and reading it (count, is_empty, capacity, find, contains, iterating) allocates nothing. Sharing allocates first, so every name for an Array sees the same elements.

An Array is Iterable<T>: for (var x in a) visits each element in index order. Every mutating operation (an element store through [], append, insert, remove_at, pop, clear, a shrinking truncate, swap, fill, retain, remove_if, resize, split_off, drain, extend_from, rotate, select_nth, partial_sort, and reverse, sort, sort_unstable or dedup of two or more elements) invalidates running iterators and slices (slice), and the next step of such a loop panics with "Array modified during iteration".

Type parameters

  • T — the element type

See also

  • ArrayIterator

Example

main(): int {
    var a = Array<int>();
    a.append(1);
    a.append(2);
    a[0] = 5;
    var total = 0;
    for (var x in a) {
        total = total + x;
    }
    assert(total == 7, "5 + 2");
    return 0;
}

Properties

count

var count: ulong { get; }

The number of elements in the Array.

capacity

var capacity: ulong { get; }

The number of elements the Array can hold before its buffer must be reallocated.

is_empty

var is_empty: bool { get; }

Whether the Array has no elements.

Constructor

Array()

construct(capacity: ulong = 0)

Creates an empty Array, optionally preallocating room for capacity elements.

With the default capacity of 0, nothing is allocated, not even the Array itself, until the Array is first written or shared (see Array). Preallocating avoids the reallocations append would otherwise perform while the Array grows to a known size.

Parameters

  • capacity — the number of element slots to allocate up front; count is still 0

Example

var a = Array<int>(16);   # a.count == 0, a.capacity == 16

Methods

iterate

[__Reads] iterate(): ArrayIterator<T>

Returns an iterator over the elements in index order; this is what for (var x in array) calls (the Iterable<T> protocol).

The iterator holds a reference to the Array, so iterating a temporary keeps it alive for the whole loop. Modifying the Array while the iterator is in use makes the iterator's next next() or current() panic, except when the Array was empty when the iterator was made: the iterator then sees no elements and ends.

Returns

  • a new iterator positioned before the first element

Example

for (var x in a) {
    total = total + x;
}

data

[__Reads] data(): __ptr<T>

Returns a pointer to the first element, for passing the elements to C, as String.c_str() does for text.

The pointer is owned by the Array. It is valid until the Array is destroyed or its buffer reallocates (append, insert, reserve, or anything else that grows it); writes through it change the elements. For an empty Array it is __null, even when capacity is reserved.

Returns

  • the address of element 0, or __null when the Array is empty

See also

  • append_from

Example

var a = Array<int>();
a.append(7);
var p = a.data();   # p[0] == 7

reserve

reserve(capacity: ulong)

Ensures the buffer has room for at least capacity elements, reallocating it when it is smaller.

Never shrinks the buffer: a capacity at or below the current one does nothing. Elements, their order, and their reference counts are unchanged, and running iterators stay valid. Growing copies the existing elements, which costs O(count).

Parameters

  • capacity — the minimum number of element slots required

Panics

  • if the buffer must grow while an I/O operation in a task is using it

Example

var a = Array<int>();
a.reserve(8);   # a.capacity >= 8
a.reserve(2);   # no effect: capacity never shrinks

grow

grow()

Makes room for one more element: when the buffer is full, doubles its capacity (to at least 4); otherwise does nothing.

append and insert call this themselves; callers rarely need it. Does not change the elements or invalidate iterators.

Panics

  • if the buffer must grow while an I/O operation in a task is using it

operator []

[__Reads] [](idx: ulong): T

Returns the element at idx; this is the indexer read a[idx].

Runs in O(1). For a struct T the result is the stored reference itself; binding it to a variable acquires it like any shared copy.

Parameters

  • idx — the zero-based position to read

Returns

  • the element at idx

Panics

  • if idx < count does not hold ("Array index read out of bounds")

Example

operator []

[](idx: ulong, value: T): T

Replaces the element at idx with value; this is the indexer write a[idx] = value.

For a struct T the slot acquires value and releases its previous occupant; assigning an element to its own slot (a[i] = a[i]) leaves counts unchanged. Only replaces an existing element: use append to add one. Invalidates running iterators, even when the value is unchanged.

Parameters

  • idx — the zero-based position to overwrite
  • value — the new element

Returns

  • the element now stored at idx (that is, value)

Panics

  • if idx < count does not hold ("Array index write out of bounds")

Example

a[0] = 42;

append

append(item: T)

Adds item to the end of the Array.

Amortized O(1): when the buffer is full it doubles (O(count) for that call). For a struct T the Array acquires a reference to item. Invalidates running iterators.

Parameters

  • item — the element to add

Panics

  • if the buffer must grow while an I/O operation in a task is using it

Example

var a = Array<int>();
a.append(1);
a.append(2);   # a holds [1, 2]

append_from

append_from(source: __ptr<T>, count: ulong)

Appends the count elements at source, in order: the way to fill an Array from a C buffer, as String(data, size) does for text.

Runs in O(count), with one copy of the whole range for a POD T. For a struct T the Array acquires a reference to each element. source must point at count valid elements, and not into this Array, which may reallocate. Invalidates running iterators.

Parameters

  • source — the first element to copy; may be __null when count is 0
  • count — the number of elements to copy

Panics

  • if the buffer must grow while an I/O operation in a task is using it

See also

  • data

Example

var a = Array<u8>();
a.append(1);
a.append(2);
var b = Array<u8>();
b.append_from(a.data(), a.count);   # b holds [1, 2]

insert

insert(idx: ulong, item: T)

Inserts item at position idx, shifting the element there and every later element up by one.

Runs in O(count - idx), plus a reallocation when the buffer is full. idx == count appends. For a struct T the Array acquires a reference to item; shifted elements keep their reference counts. Invalidates running iterators.

Parameters

  • idx — the position item will occupy; from 0 through count
  • item — the element to insert

Panics

  • if idx <= count does not hold ("Array insert index out of bounds")
  • if the buffer must grow while an I/O operation in a task is using it

Example

var a = Array<int>();
a.append(1);
a.append(3);
a.insert(1, 2);   # a holds [1, 2, 3]

remove_at

remove_at(idx: ulong): T

Removes and returns the element at idx, shifting every later element down by one.

Runs in O(count - idx). For a struct T the Array's reference is transferred to the caller, so the element stays alive as long as the result is held; shifted elements keep their reference counts. The capacity is unchanged. Invalidates running iterators.

Parameters

  • idx — the position of the element to remove

Returns

  • the removed element

Panics

  • if idx < count does not hold ("Array remove index out of bounds")

Example

var a = Array<int>();

a.append(2);
var x = a.remove_at(0);   # x == 1; a holds [2]

Runs in O(1). For a struct T the Array's reference is transferred to the caller. The capacity is unchanged. Invalidates running iterators.

clear

clear()

Removes every element, leaving the Array empty.

Runs in O(count) for a T holding references, each of which is released, and in O(1) for a plain value T (int, u8, a tuple of numbers). The capacity is kept, so refilling the Array does not reallocate. Always invalidates running iterators, even on an empty Array.

truncate

truncate(count: ulong)

Shortens the Array to its first count elements, removing the rest.

Runs in O(removed elements). For a struct T each removed element's reference is released. A count at or above the current count does nothing (the Array never grows) and leaves iterators valid; an actual shrink invalidates them. The capacity is kept.

Parameters

  • count — the number of leading elements to keep

Example

a.truncate(1);   # keeps only a[0]
a.truncate(5);   # no effect when a has fewer than 5 elements

swap

swap(a: ulong, b: ulong)

Exchanges the elements at positions a and b.

Runs in O(1). Reference counts are unchanged: the two references just trade slots. Swapping a position with itself is allowed and changes no element, but still invalidates running iterators like every swap.

Parameters

  • a — the position of the first element
  • b — the position of the second element

Panics

  • if a < count does not hold ("Array swap index out of bounds")
  • if b < count does not hold ("Array swap index out of bounds")

reverse

reverse()

Reverses the order of the elements in place.

Runs in O(count), exchanging elements pairwise, so reference counts are unchanged. An Array of fewer than two elements is left untouched and its iterators stay valid; otherwise running iterators are invalidated.

Example

a.reverse();   # [1, 2, 3] becomes [3, 2, 1]

rotate

rotate(count: ulong)

Moves the first count elements to the end, keeping the order within each part: the element at count becomes the first.

Runs in O(count of the Array), exchanging elements, so reference counts are unchanged. Rotating by 0 or by the Array's count changes nothing and leaves iterators valid; any other rotation invalidates them.

Parameters

  • count — the number of leading elements to move; from 0 through the Array's count

Panics

  • if count is more than the Array's count ("Array rotate count out of bounds")

Example

var a = [1, 2, 3, 4, 5];
a.rotate(2);   # [3, 4, 5, 1, 2]

sort

sort(compare: (T, T) => int)

Sorts the elements in place into the order compare defines. The sort is stable: elements that compare equal keep their relative order.

compare(a, b) returns a negative number when a belongs before b, 0 when their order does not matter, and a positive number when a belongs after b, the convention String.compare follows. It is a merge sort: O(count log count) calls to compare, plus a scratch buffer of count slots. Elements move between the two buffers without changing any reference count. Invalidates running iterators when there are two or more elements.

compare must not modify the Array: its elements are spread over the two buffers while the sort runs.

Parameters

  • compare — returns the order of its two arguments, as above

Panics

  • if compare modifies the Array ("Array modified during sort")

Example

var names = Array<String>();
names.append("pear");
names.append("apple");
names.sort((a, b) => a.compare(b));   # ["apple", "pear"]
var numbers = Array<int>();
numbers.append(3);
numbers.append(1);
numbers.sort((a, b) => b - a);        # descending: [3, 1]

sort_unstable

sort_unstable(compare: (T, T) => int)

Sorts the elements in place into the order compare defines, without keeping equal elements in their original order.

compare follows the convention of sort(compare). It is pattern-defeating quicksort (pdqsort): O(count log count) calls to compare in the worst case, O(count) on an Array that is already sorted or all equal, and no scratch buffer, so it is the faster sort when stability does not matter. Elements only trade slots, so no reference count changes. Invalidates running iterators when there are two or more elements.

Parameters

  • compare — returns the order of its two arguments, as for sort

Panics

  • if compare modifies the Array ("Array modified during sort")

Example

var a = [5, 1, 4, 2, 3];
a.sort_unstable((x, y) => x - y);   # [1, 2, 3, 4, 5]

select_nth

select_nth(nth: ulong, compare: (T, T) => int)

Reorders the elements so that the one at nth is the element a full sort would put there, every element before it sorts before or with it, and every element after it sorts after or with it (C++'s nth_element). Each side is otherwise in no particular order.

compare follows the convention of sort(compare). Runs in O(count) calls to compare on average and O(count log count) in the worst case, with no scratch buffer. Elements only trade slots, so no reference count changes. Invalidates running iterators.

Parameters

  • nth — the position to settle; less than count
  • compare — returns the order of its two arguments, as for sort

Panics

  • if nth < count does not hold ("Array select_nth index out of bounds")
  • if compare modifies the Array ("Array modified during sort")

Example

var a = [9, 1, 8, 2, 7, 3];
a.select_nth(2, (x, y) => x - y);   # a[2] == 3, the third smallest

partial_sort

partial_sort(count: ulong, compare: (T, T) => int)

Puts the count elements that sort first into the first count positions, in order, and leaves the rest after them in no particular order: the start of a full sort, found faster.

compare follows the convention of sort(compare). Runs in O(count of the Array + count log count) calls to compare on average, with no scratch buffer; it is not stable. Elements only trade slots, so no reference count changes. Invalidates running iterators.

Parameters

  • count — the number of leading elements to sort; from 0 through the Array's count
  • compare — returns the order of its two arguments, as for sort

Panics

  • if count is more than the Array's count ("Array partial_sort count out of bounds")
  • if compare modifies the Array ("Array modified during sort")

Example

var scores = [40, 95, 12, 77, 63];
scores.partial_sort(3, (x, y) => y - x);   # starts [95, 77, 63]

find

[__Reads] find(item: T): ulong?

Returns the position of the first element equal to item, or none when no element matches.

Runs in O(count), scanning from the front. Elements are compared with ==: when T declares an == operator (as String does) that operator decides; for any other struct T it compares references, so only the very same object matches.

Breaking change: find used to return a long that was -1 when nothing matched. It now returns ulong?: test it with is_some() (or as a condition) and read the index with value().

Parameters

  • item — the value to look for

Returns

  • the index of the first match, or none when no element matches (always none for an empty Array)

Example

var a = [3, 9, 4];
var i = a.find(9);         # i.value() == 1
var missing = a.find(7);   # missing.is_empty() == true

contains

[__Reads] contains(item: T): bool

Reports whether any element equals item, compared as find does.

Runs in O(count).

Parameters

  • item — the value to look for

Returns

  • true when find(item) finds a match

slice

[__Reads] slice(start: ulong, end: ulong): ArrayView<T>

Returns a read-only view of the elements from start up to but not including end, without copying them.

The slice holds a reference to this Array, so it cannot outlive it, and it is fail-fast like an iterator: once the Array is modified (see Array for which operations count), every later use of the slice panics, so it never reads elements that moved or were freed.

Parameters

  • start — the position of the first element in the slice
  • end — the position one past the last element; from start through count

Returns

  • a view of end - start elements

Panics

  • if start <= end and end <= count do not both hold ("Array slice out of bounds")

Example

var a = [1, 2, 3, 4, 5];
var middle = a.slice(1, 4);   # views [2, 3, 4]
var second = middle[1];       # 3

chunks

[__Reads] chunks<TElement=T>(size: ulong): ArrayChunks<TElement>

Returns an iterator over the Array in runs of size elements, as slices; the last run is shorter when size does not divide count. The same as slice(0, count).chunks(size).

Type parameters

  • TElement — the element type, T by default

Parameters

  • size — the number of elements in each run

Returns

  • an iterator over count / size runs, rounded up

Panics

  • if size is 0 ("ArrayView chunk size is 0")

Example

var rows = Array<int>();
for (var row in [1, 2, 3, 4, 5, 6].chunks(3)) {
    rows.append(row[0]);   # 1, then 4
}

windows

[__Reads] windows<TElement=T>(size: ulong): ArrayChunks<TElement>

Returns an iterator over every run of size consecutive elements, as slices, each starting one element after the one before. The same as slice(0, count).windows(size).

Type parameters

  • TElement — the element type, T by default

Parameters

  • size — the number of elements in each run

Returns

  • an iterator over count - size + 1 runs, or none when the Array is shorter than size

Panics

  • if size is 0 ("ArrayView chunk size is 0")

Example

var rises = 0;
for (var pair in [1, 3, 2, 5].windows(2)) {
    if (pair[1] > pair[0]) {
        rises = rises + 1;   # 2 in all
    }
}

binary_search_by

[__Reads] binary_search_by(order: (T) => int): ulong?

Returns the position of the element that order reports equal to the target, searching an Array sorted in the order order follows, or none when there is none.

Runs in O(log count) calls to order, which must not modify the Array. When several elements match, the first of them is found.

Parameters

  • order — returns a negative number when its argument sorts before the target, 0 when it matches, and a positive number when it sorts after

Returns

  • the index of the first matching element, or none

Panics

  • if order modifies the Array ("Array modified while a slice of it is in use")

Example

var a = [10, 20, 30];
var i = a.binary_search_by((x) => x.compare(20));   # i.value() == 1

fill

fill(value: T)

Replaces every element with value.

Runs in O(count). For a struct T every slot acquires value and releases its previous occupant. Invalidates running iterators.

Parameters

  • value — the value each element becomes

Example

retain

retain(keep: (T) => bool)

Removes every element for which keep returns false, keeping the order of the rest.

Runs in O(count) calls to keep, which sees each element once, in index order, and must not modify the Array. For a struct T each removed element is released and kept elements keep their counts. The capacity is unchanged. Invalidates running iterators.

Parameters

  • keep — returns true for an element to keep

Panics

  • if keep modifies the Array ("Array modified during retain")

Example

var a = [1, 2, 3, 4];

remove_if

remove_if(remove: (T) => bool)

Removes every element for which remove returns true, keeping the order of the rest; the opposite of retain.

Runs in O(count) calls to remove, which sees each element once, in index order, and must not modify the Array. For a struct T each removed element is released. Invalidates running iterators.

Parameters

  • remove — returns true for an element to remove

Panics

  • if remove modifies the Array ("Array modified during retain")

Example

dedup

dedup()

Removes each element equal (==) to the one before it, so a run of equal elements keeps only its first. On a sorted Array this removes every duplicate.

Runs in O(count). Elements are compared as find does. For a struct T each removed element is released. Invalidates running iterators when there are two or more elements.

Example

var a = [1, 1, 2, 3, 3, 3, 1];
a.dedup();   # [1, 2, 3, 1]

resize

resize(count: ulong, value: T)

Changes the count to count: removes elements past it, as truncate does, or appends copies of value until there are count elements.

Runs in O(difference in count), plus at most one reallocation. Invalidates running iterators when the count changes.

Parameters

Panics

append_all

append_all(rhs: Array<T>)

Appends every element of rhs, in order, to the end of this Array.

Runs in O(count of rhs), growing the buffer at most once and copying the elements in one block. rhs is unchanged, and it may be this same Array (a.append_all(a) doubles a). For a struct T each appended element is acquired once more, since both Arrays now hold it. Invalidates this Array's running iterators when rhs is not empty.

Parameters

  • rhs — the Array whose elements are copied

Panics

  • if the buffer must grow while an I/O operation in a task is using it

See also

  • +=

extend_from

extend_from(items: ArrayView<T>)

Appends every element of items, in order, to the end of this Array.

Runs in O(count of items), growing the buffer at most once. items may view this same Array. For a struct T each appended element is acquired once more. Invalidates this Array's running iterators and slices (items among them, when it views this Array) when items is not empty.

Parameters

  • items — the elements to copy

Panics

  • if the Array items views was modified since items was made ("Array modified while a slice of it is in use")
  • if the buffer must grow while an I/O operation in a task is using it

Example

var a = [1, 2];

clone

[__Reads] clone(): Array<T>

Returns a new Array holding the same elements in the same order.

Runs in O(count). The copy is shallow: for a struct T both Arrays refer to the same element objects (each acquired once more), but adding or removing elements in one does not affect the other. The new Array's capacity equals this Array's count.

Returns

  • an independent Array with the same elements

Example

var b = a.clone();
b.append(7);   # a is unchanged

copy

copy(): Array<T>

Returns a deep copy: a new Array holding a copy of each element, made with copy. This is how copy(value) copies an Array (the Copyable<Array<T>> implementation); call copy(array) rather than this method.

Unlike clone(), which shares struct elements, the result shares no element that is not thread-safe with this Array. An element that appears twice is copied once. Runs in O(count) plus the cost of copying the elements.

Returns

  • the copy

Example

var names = Array<String>();
names.append("ada");
var copied = copy(names);   # calls this method

Runs in O(count); stops at the first difference. Two empty Arrays are equal. capacity is not compared.

lower_bound

[__Reads] lower_bound(item: T): ulong

Returns the first position at which item could be inserted while keeping this sorted Array sorted: the index of the first element that does not sort before item (in compare order), or count when every element does.

ArrayView

[Value] struct ArrayView<T>

A read-only view of a run of an Array's elements, made by Array.slice, that lets a function take "some of the elements" without copying them.

A slice holds a reference to its Array, so the Array lives at least as long as the slice. It is fail-fast like ArrayIterator: once the Array is modified (see Array for which operations count), every later use of the slice panics with "Array modified while a slice of it is in use" instead of reading elements that moved or were freed. Make a new slice after changing the Array.

A slice is Iterable<T>: for (var x in slice) visits its elements in order.

Type parameters

  • T — the element type of the Array

See also

  • Array.slice

Example

total(values: ArrayView<int>): int {
    var sum = 0;
    for (var x in values) {
        sum = sum + x;
    }
    return sum;
}

var a = [1, 2, 3, 4];
var tail_sum = total(a.slice(2, 4));   # 7
