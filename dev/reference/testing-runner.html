The Pepper Programming Language

TestRunner

The main of a test program: TestRunner holds the tests of the files it was built from and answers pep-test's --list and --run NAME.

Source: runtime/testing/runner.pep

keep_for_the_program

keep_for_the_program(body: () => void)

Runs body and lets what it leaves allocated stay without failing the test's leak check: for what a program makes once, on first use, and keeps until it ends, such as a lazily made global (async.Lazy), when a test is the first to use it.

Call it at the start of the test, with the first use alone, so the rest of the test is still checked.

Parameters

  • body — the code that makes what the program keeps

Example

import tls;

[Test]
connects() {
    # The first connector loads the TLS library, which stays loaded.
    keep_for_the_program(() => {
        tls.TlsConnector.create();
    });
    # ... the checks, under the leak check as usual
}

TestRunner

struct TestRunner

The tests of one test program, which its generated main registers and then runs with the program's arguments.

The program answers two requests, both made by pep-test:

  • --list prints one line per test, its fields separated by tabs: the name, file:line, returns or panics (for [ShouldPanic]), and the text the panic must contain (empty for any panic or none).
  • --run NAME [--timeout SECONDS] runs the test NAME (or file::NAME, which tells apart tests of one name in two files) and exits with 0 when it returns, or with 1 when it left an allocation behind (or released one too many); a panic aborts the program. With a timeout above 0, a test still running after that many seconds ends the program with exit status 124 and a message on standard error. However the program ends (the test returns, panics, crashes or times out), every process the test started ends with it (a job object on Windows, a process group elsewhere), so none holds pep-test's pipes to its output open.
