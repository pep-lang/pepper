The Pepper Programming Language

Types and variables

This chapter covers the values every Pepper program is built from: numbers, booleans and strings, the variables that hold them, and the operators that combine them.

Built-in types

Integers

Pepper has signed and unsigned integers of 8, 16, 32 and 64 bits. Each width has a short name (i32) and a descriptive alias (int). The two names are the same type, so you can use whichever reads better and assign freely between them.

BitsSignedUnsigned
8i8, charu8, byte
16i16, shortu16, ushort
32i32, intu32, uint
64i64, longu64, ulong

int is 32 bits and long is 64 bits on every platform. sizeof<T>() gives the size of a type in bytes.

Integer literals are written in decimal (42) or hexadecimal (0xFF). A literal on its own is an int when its value fits in an int, and a long otherwise, so var big = 3000000000; is a long. It takes another type when you store it in a variable of that type (u64 huge = 9000000000000000000;). A hexadecimal literal is a 64-bit bit pattern: u64 all = 0xFFFFFFFFFFFFFFFF; sets every bit.

# Integer types: widths, signedness, wraparound and conversions.
main(): int {
    # Each width has a short name and a descriptive alias.
    i8 tiny = -100;       # same type as char
    u8 octet = 200;       # same type as byte
    i16 small = -30000;   # same type as short
    u16 port = 65000;     # same type as ushort
    i32 count = 2000000;  # same type as int
    u32 mask = 4000000000; # same type as uint
    i64 big = 9000000000; # same type as long
    u64 huge = 9000000000000000000;  # same type as ulong

    assert(sizeof<char>() == 1 && sizeof<short>() == 2, "8 and 16 bits");
    assert(sizeof<int>() == 4 && sizeof<long>() == 8, "32 and 64 bits");

    # An alias names the same type, so assigning between them is lossless.
    short s = small;
    assert(s == -30000, "short and i16 are one type");

    # Storing a value that does not fit wraps around, as in C.
    u16 wrap = 65535;
    wrap = wrap + 1;
    assert(wrap == 0, "u16 wraps from 65535 to 0");
    i16 overflow = 32767;
    overflow += 1;
    assert(overflow == -32768, "i16 wraps from 32767 to -32768");

    # Widening keeps the value: signed types sign-extend, unsigned zero-extend.
    long widened = small;
    assert(widened == -30000, "i16 widens to long");
    assert((tiny as u8) == 156, "-100 as u8 is 156");
    assert((octet as i8) == -56, "200 as i8 is -56");

    # Narrowing with 'as' keeps the low bits.
    assert((70000 as u16) == 4464, "70000 as u16 keeps the low 16 bits");

    # Hexadecimal literals.
    assert(0xFF == 255, "0xFF is 255");
    assert(count + big > 0 && mask > 0 && huge > 0 && port > 0, "all in range");
    return 0;
}

Storing a value that does not fit in the destination keeps its low bits, as in C: a u16 holding 65535 becomes 0 when you add 1 and store the result, and 70000 as u16 is 4464.

A decimal literal larger than the largest long (9223372036854775807), or a hexadecimal literal with more than 64 bits, is an error:

main.pep:2:13: error: integer literal is too large to be represented in a 64-bit integer
    2 |     var f = 99999999999999999999;
      |             ^~~~~~~~~~~~~~~~~~~~

Floating point

float is a 32-bit and double a 64-bit IEEE 754 number (f32 and f64 are aliases). A literal with a decimal point or an exponent, such as 0.25 or 1e3, is a double.

Booleans

bool holds true or false. Comparisons and the logical operators produce a bool. In arithmetic a bool counts as 0 or 1, and print(true) prints 1.

Characters

A character literal is one ASCII character between single quotes: 'a', '"', '#'. Its value is the character’s code, and its type is byte (u8), the type of one byte of a UTF-8 string. Like any byte it widens to the other integer types, so it compares with, and stores into, an int or a char as well:

# Character literals are bytes.
is_lower(c: int): bool {
    return c >= 'a' and c <= 'z';
}

main(): int {
    var letter = 'a';   # a byte holding 97
    assert(letter == 97, "a character literal is its ASCII code");
    assert('"' == 34 and '\n' == 10 and '\'' == 39, "escapes work as in strings");

    # Compare the bytes of a String with character literals.
    var text = "x = 1";
    var bytes = text.c_str();
    assert(bytes[0] == 'x' and bytes[2] == '=', "compare raw bytes");
    assert(is_lower(bytes[0]), "a byte widens to int");

    # Arithmetic works as on any integer.
    int digit = bytes[4] - '0';
    assert(digit == 1, "the digit's value");

    print(letter);
    return 0;
}

The escapes are the same as a string’s (see the table under Strings), plus \xHH for any byte, '\xFF' included. A character literal holds exactly one ASCII character; for anything else use a string:

main.pep:2:13: error: character literal may only contain one character; use a string for more
    2 |     var x = 'ab';
      |             ^~~~
main.pep:2:14: error: character literal must be a single ASCII character; use a string for other characters
    2 |     var x = 'é';
      |              ^

char is an 8-bit signed integer, the same type as i8, used mostly for C strings (__ptr<char>). The ASCII characters have the same value as a char and as a byte; '\xFF' is 255 as a byte but -1 read through a char. Text is a String, and a single character of it is a one-code-point String.

Strings

String is a UTF-8 string. A string literal such as "hello" is a String value, except where it is stored or passed as a __ptr<char>: there it is the literal’s NUL-terminated bytes (see Passing strings). + joins two strings into a new one, == and != compare contents, length() counts code points, size() counts bytes, and s[i] gives the code point at index i as a one-code-point String.

# String literals are String values.
main(): int {
    var language = "Pepper";
    assert(language.length() == 6, "6 code points");

    # + makes a new String; == compares contents.
    var message = "Hello, " + language;
    assert(message == "Hello, Pepper", "concatenation");
    assert(message != language, "different contents");

    # Strings are UTF-8. length() counts code points, size() counts bytes.
    var word = "héllo";
    assert(word.length() == 5, "5 code points");
    assert(word.size() == 6, "6 bytes: 'é' takes 2");
    assert(word[1] == "é", "indexing yields a one-code-point String");

    # A String is a reference: both names see an append.
    var alias = message;
    message.append("!");
    assert(alias == "Hello, Pepper!", "one object, two references");

    print(message);
    return 0;
}

A String is a reference type: var alias = message; makes a second reference to the same object rather than a copy, so a change made with append shows through both names. Memory and reference counting explains how references work, and the String reference lists every method.

to_string turns any integer into its decimal text. For parsing and generating text, byte_at and substr_bytes work in bytes (the offsets find returns), compare and <, <=, >, >= order strings byte by byte (code-point order for UTF-8), lines() splits on "\n" or "\r\n", trim_end() drops trailing whitespace, and repeat(n) joins n copies. A StringBuilder builds a long String from many pieces without recopying the text built so far on every append:

# Numbers to text, byte-level access, ordering, and building text in pieces.
main(): int {
    # to_string turns any integer into its decimal text.
    var line = 3;
    var where = to_string(line) + ":" + to_string(-7);
    assert(where == "3:-7", "to_string");

    # byte_at and substr_bytes count bytes, so they work with find's offsets.
    var setting = "indent=4";
    var eq = setting.find("=") as ulong;
    assert(setting.byte_at(eq) == '=', "byte_at compares with a character literal");
    assert(setting.substr_bytes(0, eq) == "indent", "the bytes before '='");

    # compare, <, <=, > and >= order strings byte by byte.
    assert("apple" < "banana", "ordering");
    assert("b".compare("a") > 0, "compare is negative, 0 or positive");

    # lines() splits on "\n" or "\r\n"; trim_end() drops trailing whitespace.
    var lines = "one  \r\ntwo\n".lines();
    assert(lines.count() == 2, "no empty line after the final newline");
    assert(lines[0].trim_end() == "one", "trim_end");

    # repeat joins copies; StringBuilder appends without recopying the text.
    var out = StringBuilder();
    for (var text in lines) {
        out.append(" ".repeat(4)).append(text.trim_end()).append("\n");
    }
    assert(out.to_string() == "    one\n    two\n", "StringBuilder");
    return 0;
}

An interpolated string puts variables’ text into a string literal: $"line {line}: {message}". String interpolation covers which values it accepts.

A backslash in a string literal starts an escape sequence, as in C and Rust:

EscapeCharacter
\nnewline
\ttab
\rcarriage return
\0the zero byte
\\a backslash
\"a double quote
\'a single quote
\xHHthe ASCII character with hexadecimal code HH, at most \x7F (any byte in a character literal)
\u{H...}the Unicode code point with hexadecimal code H... (1 to 6 digits)
 
print("name:\t\"Pepper\"");   # name:	"Pepper"
print("caf\u{e9}");            # café

Any other character after a backslash is an error:

main.pep:2:13: error: unknown escape sequence '\q'
    2 |     print("a\qb");
      |             ^~

Other built-in types

  • void means “no value”. It is the return type of a function that returns nothing.
  • Array<T> is a growable array of T; int[] is shorthand for Array<int>, and int[][] for Array<Array<int>>. See Array.
  • Optional<T> is a value that may be missing; int? is shorthand for Optional<int>. See Optional values.
  • HashMap<K, V> and HashSet<K> are hash tables. See HashMap and HashSet.
  • Result<TValue, TError> and Error describe operations that can fail. See Error handling with Result.
  • Atomic<T> is a value that threads can update safely. See Atomics and Threads and shared data.

Raw pointers and __null

For talking to C, Pepper has raw pointers, written __ptr<T> (for example __ptr<char> or __ptr<void>), and the null pointer literal __null:

var p: __ptr<void> = __null;
assert(p == __null, "p is null");

Most programs never need them. Calling C covers pointers in full.

Naming conventions

Primitive types and keywords are lowercase: int, float, bool, var, while. Structs, including the ones the runtime provides, are PascalCase: String, Array<T>, HashMap<K, V>, Result<TValue, TError>. Follow the same convention for your own structs. Functions and variables are usually written in snake_case.

Identifiers are made of ASCII letters, digits and underscores, and cannot start with a digit. Avoid names that start with two underscores: the compiler and runtime use them for their own names, such as __ptr and __null.

Variables

Declare a variable with var and let Pepper infer its type from the initial value, or write the type yourself. Prefer var whenever the type is obvious from the value.

# Declaring variables: inferred, explicitly typed, constant, and module-level.

# Module-level variables (globals) live for the whole program. Any thread
# can reach them, so they are const and of a thread-safe type: a number, or
# an Atomic for state that changes.
const MAX_REQUESTS = 10;
const request_count = Atomic<int>(0);
const total_bytes = Atomic<long>(0);

record(bytes: int) {
    request_count.fetch_add(1);
    total_bytes.fetch_add(bytes);
}

main(): int {
    # 'var' infers the type from the initializer.
    var answer = 42;          # int: integer literals are int
    var ratio = 0.25;         # double: floating-point literals are double
    var ready = true;         # bool
    var name = "Pepper";      # String

    # Write the type first, C style...
    int width = 80;
    float scale = 1.5;

    # ...or after the name with a colon.
    var height: int = 24;
    var offset: long = 5000000000;

    # A variable declared without a value starts at zero.
    var hits: int;
    assert(hits == 0, "numbers start at zero");

    # 'const' declares a name that should not be reassigned.
    const LIMIT = 3;

    record(100);
    record(250);
    assert(request_count.load() == 2, "two requests recorded");
    assert(total_bytes.load() == 350, "350 bytes in total");
    assert(request_count.load() < MAX_REQUESTS, "globals are visible in every function");

    assert(answer + width + height == 146, "sum of ints");
    assert(ratio * 4 == 1.0 && scale == 1.5, "floating point");
    assert(ready && name == "Pepper", "bool and String");
    assert(offset > 4000000000 && LIMIT == 3, "long and const");
    return 0;
}

The three forms are:

  • var name = value; infers the type from the value.
  • Type name = value; is the C style, with the type first.
  • var name: Type = value; puts the type after the name.

A variable declared without a value starts out as zero: 0 for numbers, false for bool, and null for a struct type such as String. Give struct variables a value before you use them.

When var infers the type of an arithmetic expression, it takes the type the arithmetic produces under C’s rules (see Arithmetic follows C): var m = 1 + 0.5; is a double holding 1.5, and with u8 small = 250;, var s = small + 10; is an int holding 260.

Constants

const declares a name that you do not intend to change:

const LIMIT = 3;
const RATIO: double = 0.5;

Assigning to a const, with =, a compound assignment, ++ or --, is an error:

main.pep:5:5: error: cannot assign to const variable 'LIMIT'
    5 |     LIMIT = 4;
      |     ^~~~~
main.pep:1:7: note: 'LIMIT' declared const here
    1 | const LIMIT = 3;
      |       ^~~~~

Module-level variables

A variable declared outside any function is a module-level (global) variable. It exists for the whole run of the program and every function in the file can read it. Its initializer can be any expression, including a function call, and runs before main. Like other top-level declarations, a global is private to its file unless you mark it export (see Visibility).

Any function can run on any thread, so every thread can reach a global. It must therefore be declared const and have a thread-safe type, such as a number, an Atomic<T>, a ThreadLocal<T>, or a [Shared] struct (see Module-scope variables). A global that changes is an Atomic<T>:

const MAX_RETRIES = 3;
const requests = Atomic<long>(0);   # changed with requests.fetch_add(1)

Casting with as

value as Type converts a value to another type explicitly, like static_cast in C++:

var ratio = 7.9;
var whole = ratio as int;   # 7
var wide = whole as long;
  • Floating point to integer truncates toward zero: -7.9 as int is -7.
  • Integer to a narrower integer keeps the low bits: 70000 as u16 is 4464.
  • Integer to a wider integer sign-extends a signed source and zero-extends an unsigned one: (-1 as i16) as long is -1, and (65535 as u16) as long is 65535.
  • Casting between unrelated struct types is a compile error (cannot cast to Q).

as binds more tightly than the arithmetic operators, so x * 10 as int means x * (10 as int). Put parentheses around the expression you want to convert: (x * 10) as int. C-style casts such as (int)x do not exist.

Many conversions also happen without as: assigning or passing a number to a variable or parameter of another numeric type converts it, as in C, including narrowing conversions (int n = 2.7; stores 2).

Arithmetic follows C

Arithmetic on numbers behaves exactly as it does in C (the “usual arithmetic conversions”), so code ported from C gives the same results:

  • Integer promotion. Types narrower than int (char, u8, short, u16, and bool) are converted to int before any arithmetic. The sum of two chars is an int, so 100 + 100 gives 200 rather than wrapping at 8 bits.
  • Mixed widths use the wider type: int + long is a long.
  • Signed and unsigned. When both operands have the same width and one is unsigned, the operation is unsigned: comparing int -1 with uint 1 treats -1 as 4294967295, so -1 < 1 is false for those types.
  • Integer and floating point gives floating point: 3 * 0.5 is 1.5.
  • Division of integers truncates toward zero (-7 / 2 is -3), and % takes the sign of the left operand (-7 % 3 is -1).
  • Shifts take the type of the (promoted) left operand. >> keeps the sign for signed types and fills with zeros for unsigned types.
  • Overflow of unsigned arithmetic wraps around. As in C, signed overflow, division by zero, and shifting by the operand’s width or more are not defined; do not rely on what they do.
# Arithmetic follows C's rules for promotion and conversion.
main(): int {
    # Integer division truncates toward zero; % takes the sign of the left side.
    assert(7 / 2 == 3, "7 / 2 is 3");
    assert(-7 / 2 == -3, "-7 / 2 is -3");
    assert(-7 % 3 == -1, "-7 % 3 is -1");

    # Types narrower than int are promoted to int before arithmetic,
    # so the sum of two chars does not wrap at 8 bits...
    char a = 100;
    char b = 100;
    int sum = a + b;
    assert(sum == 200, "char + char is computed as int");

    # ...but storing the result back into a char does.
    char c = a + b;
    assert(c == -56, "200 does not fit in a char");

    # Mixing signed and unsigned of the same width is unsigned, as in C.
    int minus_one = -1;
    uint one = 1;
    assert(!(minus_one < one), "-1 converts to 4294967295 when compared with a uint");
    uint zero = 0;
    assert(zero - 1 == 4294967295, "unsigned arithmetic wraps");

    # Mixing an integer with a floating-point value gives floating point.
    int whole = 3;
    double half = 0.5;
    double product = whole * half;
    assert(product == 1.5, "3 * 0.5 is 1.5");

    # 'as' converts explicitly. Floating point to integer truncates toward zero.
    assert((7.9 as int) == 7, "7.9 as int is 7");
    assert((-7.9 as int) == -7, "-7.9 as int is -7");
    assert(((whole as double) / 2) == 1.5, "divide as double");

    # Assignment converts implicitly, including from double to int.
    int truncated = 2.7;
    assert(truncated == 2, "2.7 stored in an int is 2");

    # Shifts: >> is arithmetic for signed types and logical for unsigned types.
    assert(-8 >> 1 == -4, "signed shift keeps the sign");
    uint bits = 0x80000000;
    assert(bits >> 31 == 1, "unsigned shift fills with zeros");
    return 0;
}

Operators

# Operators on numbers and booleans.
main(): int {
    # Arithmetic.
    assert(2 + 3 * 4 == 14, "* binds tighter than +");
    assert((2 + 3) * 4 == 20, "parentheses group");
    assert(17 % 5 == 2, "remainder");
    assert(-(3) == -3, "negation");

    # Exponentiation is right-associative: 2 ** 3 ** 2 is 2 ** 9.
    assert(2 ** 10 == 1024, "power");
    assert(2 ** 3 ** 2 == 512, "right-associative");

    # Comparison yields a bool.
    var small = 3 < 5;
    assert(small, "3 < 5");
    assert(5 >= 5 && 4 <= 5 && 6 > 5 && 5 == 5 && 5 != 6, "comparisons");
    # On numbers, `===` and `!==` are the same as `==` and `!=`.
    assert(5 === 5 && 5 !== 6, "identity on numbers");

    # Logical operators; 'and' and 'or' are spellings of && and ||.
    var t = true;
    var f = false;
    assert(t && !f, "and, not");
    assert(f || t, "or");
    assert(t and (f or t), "word forms");

    # Bitwise operators.
    assert((6 & 3) == 2, "and");
    assert((6 | 3) == 7, "or");
    assert((6 ^ 3) == 5, "exclusive or");
    assert(~0 == -1, "complement");
    assert(1 << 4 == 16 && 256 >> 2 == 64, "shifts");

    # Compound assignment and increment.
    var n = 5;
    n += 3;   # 8
    n -= 2;   # 6
    n *= 4;   # 24
    n /= 5;   # 4
    n %= 3;   # 1
    n <<= 3;  # 8
    n >>= 1;  # 4
    n &= 6;   # 4
    assert(n == 4, "compound assignment");
    n++;
    ++n;
    n--;
    assert(n == 5, "increment and decrement");

    # The conditional (ternary) operator.
    var sign = n > 0 ? "positive" : "not positive";
    assert(sign == "positive", "ternary");
    return 0;
}

&& and || short-circuit: the right operand is evaluated only when the left one does not decide the result, so items.count() > 0 && items[0] == 1 never reads items[0] from an empty array.

Unary operators nest: -~x is -(~x), and !!x is !(!x), which turns a number into a bool. A struct can define its own operators, the truth test !! included (see Operators).

** raises an integer to an integer power, and is right-associative: 2 ** 3 ** 2 is 2 ** 9. The exponent can be any integer expression. A negative exponent gives the truncated real result: 1 for a base of 1, 1 or -1 for a base of -1, and 0 otherwise (2 ** -1 is 0).

Some operators have limits today:

  • ** works only on integers. A floating-point operand is a compile error (unsupported op Pow).

Operators bind in this order, tightest first:

  1. Postfix: calls f(x), indexing a[i], member access a.b, x++, x--
  2. **
  3. as
  4. Unary +, -, !, ~
  5. Prefix ++, --
  6. *, /, %
  7. +, -
  8. <<, >>
  9. <, <=, >, >=
  10. ==, !=, ===, !==
  11. &
  12. |, ^
  13. &&, and
  14. ||, or
  15. ? :
  16. = and the compound assignments (right-associative)

As in C, & binds more loosely than ==, so write (flags & mask) == mask with the parentheses.
