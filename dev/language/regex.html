The Pepper Programming Language

Regular expressions

The regex module finds patterns in text: test whether text matches, find each match and its capture groups, and replace or split by a pattern.

# Regular expressions: match, capture, iterate, replace and split.
import regex;

main(): int {
    # Compile once, reuse. Backslashes are doubled inside a string literal.
    var date = regex.Regex("(?<year>\\d{4})-(\\d{2})-(\\d{2})");
    assert(date.is_match("due 2026-10-01"), "a date somewhere");

    # The first match, with its groups. Positions are byte offsets.
    var found = date.find("due 2026-10-01").value();
    assert(found.text() == "2026-10-01" && found.start() == 4, "where");
    assert(found.group(2).value() == "10", "a numbered group");
    assert(found.group("year").value() == "2026", "a named group");

    # Every match, left to right.
    var total = 0;
    for (var number in regex.Regex("\\d+").find_all("1 22 333")) {
        total += int.parse(number.text()).value();
    }
    assert(total == 356, "1 + 22 + 333");

    # Replace with group references, and split.
    var swapped = regex.Regex("(\\w+)@(\\w+)").replace_all("ann@home bob@work", "$2:$1");
    assert(swapped == "home:ann work:bob", "groups swapped");
    var parts = regex.Regex("\\s*,\\s*").split("a , b,c");
    assert(parts.count == 3 && parts[1] == "b", "three pieces");

    # Flags go inside the pattern: (?i) ignores case.
    assert(regex.Regex("(?i)^hello").is_match("HeLLo there"), "any case");

    # An invalid pattern from outside the program: parse reports it.
    var bad = regex.Regex.parse("(unclosed");
    assert(bad.is_err(), "missing ')'");
    return 0;
}

Compiling a pattern

  • regex.Regex(pattern) compiles a pattern and panics when it is invalid. Use it for patterns written in the program.
  • regex.Regex.parse(pattern) returns a Result<Regex> instead, whose error names the problem and its byte offset: invalid regex '(a': missing ')' at offset 0. Use it for patterns that come from input.
  • Compile once and reuse the Regex; compiling costs more than a search.
  • Regex.escape(text) escapes every character with a meaning in a pattern, so the result matches text literally.

A pattern is a String, so each backslash is doubled in a string literal: "\\d+" is the pattern \d+.

Searching

MethodResult
is_match(text)whether there is a match anywhere; the fastest test
find(text)the leftmost Match, or Empty
find_at(text, start)the leftmost match starting at or after byte start
find_all(text)an iterator over every match, left to right, without overlaps
replace(text, replacement)text with the first match replaced
replace_all(text, replacement)text with every match replaced
split(text)the pieces of text between matches

A Match has text(), start() and end() (byte offsets, as String.find returns, for use with substr_bytes), and group(index) or group(name), which give the group's text or Empty when the group did not take part (as (a) in (a)|b matching b). Group 0 is the whole match; groups are numbered by their opening (. group_range(index) gives a group's offsets.

Matching is leftmost-first, as in Perl: the match that starts earliest wins, and among those, a greedy repetition prefers more and alternation prefers its earlier branch (a|ab finds a in ab).

find_all skips an empty match that comes right after the previous match, so a* finds a twice in aba, not also an empty match between them.

In a replacement, $1 or ${1} stands for group 1, ${name} for a named group, $0 for the whole match and $$ for a $. A group that did not take part gives empty text. Use braces when a digit or letter follows: ${1}0, not $10.

Syntax

The syntax is RE2's, the one Go's regexp and Rust's regex crate use.

Flags go in the pattern: (?i) makes the rest of the enclosing group case-insensitive, (?i:x) only x, and (?-i) turns a flag off.

Text

  • A pattern works on code points: . and [^a] match one whole code point, such as é or 🙂, never part of one.
  • \d, \w, \s, \b, the POSIX classes and case-insensitive matching are ASCII-only: \w does not match é.
  • Positions are byte offsets, like String.find and substr_bytes, not the code point positions of substr.

Linear time

Matching never backtracks. The engine (a Pike VM, as in RE2) steps every possible match through the text together, so a search takes time proportional to the size of the text times the size of the pattern, whatever both are. A pattern such as (a*)*b, which takes exponential time in a backtracking engine, is safe on untrusted input.

The price is two features that need backtracking. A pattern that uses one fails to compile:

  • Backreferences (\1): backreferences are not supported
  • Lookaround ((?=x), (?!x), (?<=x), (?<!x)): lookaround is not supported

Groups nest at most 250 deep, and a pattern whose compiled program would exceed 100,000 instructions (from large counted repetitions such as (a{1000}){1000}) is rejected.

Threads

A Regex never changes once it is compiled, and it is [Shared]: one Regex can serve every thread at once, so a pattern the program uses often can be compiled once at module scope:

import regex;

const identifier = regex.Regex("^[A-Za-z_][A-Za-z0-9_]*$");

is_identifier(text: String): bool {
    return identifier.is_match(text);
}

Each search keeps its working state to itself, and a Match (which holds the searched String) stays on the thread that found it.
