The Pepper Programming Language

Encodings: text, base64 and UUIDs

Networked programs keep writing bytes as text and back: credentials in an HTTP header, a token in a URL, a value in a query string, an identifier in a database. Files, protocols and C libraries also hand over text in encodings other than UTF-8. These live in a few places:

# Encodings: base64, hexadecimal, percent-escapes and form data, and UUIDs.
import base64;
import digest;
import uuid;

main(): int {
    # base64: an HTTP basic authentication header, and a URL-safe,
    # unpadded token as JSON Web Tokens write them.
    var credentials = base64.encode("ada:secret".bytes());
    assert(credentials == "YWRhOnNlY3JldA==", "standard, padded");
    var token = base64.encode([251, 255, 0], true, false);
    assert(token == "-_8A", "URL-safe, unpadded");
    assert(base64.decode(token, true).value()[0] == 251, "decoded");
    assert(base64.decode("not base64!").is_err(), "rejected");

    # Hexadecimal, both ways.
    assert(digest.from_hex(digest.to_hex([1, 171])).value()[1] == 171, "round trip");

    # Percent-escapes for one path segment or query value, and form data.
    assert(Uri.encode("a b&c") == "a%20b%26c", "escaped");
    var query = Uri.encode_form([("q", "pepper lang"), ("page", "2")]);
    assert(query == "q=pepper+lang&page=2", "form-encoded");
    var pairs = Uri.decode_form(query).value();
    assert(pairs[0].1 == "pepper lang", "decoded");

    # UUIDs: random (v4) and time-ordered (v7).
    var id = uuid.Uuid.v4();
    assert(uuid.Uuid.parse(id.to_string()).value() == id, "round trip");
    assert(uuid.Uuid.v7().version() == 7, "time-ordered");
    return 0;
}

Text encodings

A String always holds UTF-8. The text module converts text to and from the bytes of an encoding (u8[]), for files, network protocols and C libraries that use another one:

# Text in other encodings: encode a String to bytes, decode bytes back.
import text;

main(): int {
    var greeting = "héllo 🙂";

    # UTF-8 is what a String holds; decode checks the bytes.
    var utf8 = text.Utf8.encode(greeting);
    assert(utf8.count == 11, "é takes two bytes, 🙂 four");
    assert(text.Utf8.decode(utf8).value() == greeting, "round trip");

    # UTF-16: two bytes per unit, little-endian unless asked otherwise.
    var utf16 = text.Utf16.encode(greeting);
    assert(utf16.count == 16, "🙂 takes a surrogate pair");
    assert(text.Utf16.decode(utf16).value() == greeting, "round trip");

    # ASCII has no é: strict gives none, lossy writes '?'.
    assert(text.Ascii.encode(greeting).is_empty(), "not ASCII");
    assert(text.Ascii.encode_lossy("é").count == 1, "one '?'");

    # Code page 437, as old zip archives name entries: é is 0x82, and every
    # byte decodes, so decode gives a String.
    var dos = text.CodePage437.encode("café").value();
    assert(dos.count == 4 && dos[3] == 0x82, "one byte each");
    assert(text.CodePage437.decode(dos) == "café", "round trip");
    assert(text.CodePage437.encode(greeting).is_empty(), "no 🙂 in code page 437");

    # Strict decoding rejects invalid bytes; lossy decoding replaces them.
    var bad = Array<u8>();
    bad.append(104);
    bad.append(255);
    assert(text.Utf8.decode(bad).is_empty(), "0xFF is never UTF-8");
    assert(text.Utf8.decode_lossy(bad) == "h\u{FFFD}", "replaced");
    return 0;
}
TypeEncoding
text.Utf8UTF-8. encode copies the String's bytes; decode checks them. is_valid checks bytes without decoding, and find_invalid gives the offset of a String's first invalid byte. code_point_at reads one code point and append_code_point writes one.
text.Utf16UTF-16, two bytes per code unit, little-endian by default (encode(s, true) and decode(bytes, true) for big-endian). A code point past U+FFFF takes a surrogate pair.
text.AsciiASCII: code points below 128, one byte each. is_ascii checks a String.
text.CodePage437Code page 437, the IBM PC character set that old zip archives use for entry names: ASCII below 128, and one accented letter, Greek letter or box-drawing symbol for each byte above. Every byte decodes, so decode gives a String, not an Optional.
  • decode is strict: it gives Empty when the bytes are not valid in the encoding (a stray UTF-8 continuation byte, an unpaired UTF-16 surrogate, an odd UTF-16 byte count, an ASCII byte of 128 or more).
  • decode_lossy always succeeds: whatever is invalid becomes U+FFFD, the replacement character.
  • Ascii.encode gives Empty for text with a code point past 127, and CodePage437.encode for a character the code page lacks; encode_lossy writes ? for each instead.
  • No byte-order mark is written, and one that is read stays in the text.
  • io.File.read_string decodes with text.Utf8.decode, and an HTTP body's text() with decode_lossy.

The reference lists every function.

Base64

base64.encode(bytes) writes RFC 4648 base64 with the standard alphabet (A-Z a-z 0-9 + /) and = padding. Two optional arguments change that: url_safe = true uses - and _ in place of + and /, so the text can go in a URL or a file name, and padded = false leaves off the padding, as JSON Web Tokens do.

base64.decode(text) returns a Result<u8[]>. It accepts text with or without padding (pass url_safe = true for the other alphabet), and is strict otherwise: whitespace, a character outside the alphabet, a length no encoding gives, or unused bits that are not zero is an error. Remove line breaks from PEM or MIME text before decoding it. The functions work on whole arrays; there is no streaming encoder yet.

Hexadecimal

digest.to_hex(bytes) writes two lowercase digits per byte, and digest.from_hex(text) reads them back, in either case; an odd length or a character that is not a digit is an error.

Percent-escapes and form data

Uri.encode(text) escapes every byte outside RFC 3986's unreserved set (A-Z a-z 0-9 - . _ ~), so the result is safe as one path segment or one query value: /, ?, &, = and % are escaped too. Uri.decode reverses it.

Uri.encode_form(pairs) writes names and values as application/x-www-form-urlencoded, the format of HTML forms and most query strings (q=pepper+lang&page=2), and Uri.decode_form(text) reads it back into an Array<(String, String)>, in order, keeping repeated names. In this format a space is +.

UUIDs

uuid.Uuid is a 128-bit identifier (RFC 9562), a value struct of two ulong halves, high and low, so == and hash work and it can key a map.

  • Uuid.v4() makes a random one: 122 bits from the operating system's secure source.
  • Uuid.v7() puts the wall clock's Unix time in milliseconds first, then 74 random bits, so ids made later sort later, both as values and as text. That keeps database indexes compact. Ids made in the same millisecond are in no particular order.
  • Uuid.parse(text) reads the usual form, 0190163d-8694-739b-aea5-966c26f8ad91, in either case, and to_string() (or interpolation) writes it in lowercase.
  • version() returns the version digit and bytes() the 16 bytes, for a database or a binary format.

The full API is in the reference: base64, uuid, hexadecimal and Uri.
