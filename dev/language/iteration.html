The Pepper Programming Language

Iteration

A for loop visits each element of a collection in turn. You can loop over an Array, over the code points of a String, and over any type of your own that follows the iterator protocol.

Looping over an array

for (var x in source) { ... } runs the body once per element, with x bound to the element:

struct Item {
    int Value;
    construct(this.Value = 0) {}
}

make_items(): Array<Item> {
    var items = Array<Item>();
    items.append(Item(20));
    items.append(Item(22));
    return items;
}

main(): int {
    var nums = Array<int>();
    nums.append(1);
    nums.append(2);
    nums.append(39);

    # The basic loop: x takes each element in order.
    var total = 0;
    for (var x in nums) {
        total = total + x;
    }
    assert(total == 42, "sum of the elements");

    # The loop variable may be typed, and the parentheses are optional.
    long wide = 0;
    for (long x in nums) {
        wide = wide + x;
    }
    for var x: int in nums {
        wide = wide - x;
    }
    assert(wide == 0, "typed loop variables");

    # break and continue work as in a while loop.
    var odd = 0;
    for (var x in nums) {
        if (x % 2 == 0) {
            continue;
        }
        if (x > 10) {
            break;
        }
        odd = odd + x;
    }
    assert(odd == 1, "only 1 is odd and below 10");

    # A struct element is shared: changing a field changes the element,
    # but rebinding the loop variable does not touch the array.
    var items = make_items();
    for (var item in items) {
        item.Value = item.Value * 10;
        item = Item(99);
    }
    assert(items[0].Value == 200, "first element was updated");
    assert(items[1].Value == 220, "second element was updated");

    # Iterating a temporary keeps it alive for the whole loop.
    var sum = 0;
    for (var item in make_items()) {
        sum = sum + item.Value;
    }
    assert(sum == 42, "temporary array stays alive");

    # The loop is shorthand for driving the iterator yourself.
    var it = nums.iterate();
    var manual = 0;
    while (it.next()) {
        manual = manual + it.current();
    }
    assert(manual == 42, "the same elements, by hand");

    # Modifying the array after the loop is fine.
    nums.append(100);
    assert(nums.count() == 4, "appended after the loop");
    return 0;
}

The example shows each part of the loop:

  • The loop variable can be declared with var or with a type: for (var x in nums), for (long x in nums), and for (var x: int in nums) all work.
  • The parentheses are optional, as with if and while: for var x in nums { ... }. The braces are required.
  • break and continue work as they do in a while loop.
  • The loop variable is a copy, like any var. Assigning a new value to it does not change the collection. For a struct element, though, the copy is another reference to the same object (see Memory and reference counting), so item.Value = ... does change the element.
  • A temporary source stays alive. The loop holds a reference to what it iterates, so for (var item in make_items()) is safe.

Looping over a string

A String yields its code points one at a time. Each one is a String holding a single code point, the same value that indexing gives you (word[i]):

main(): int {
    var word = "héllo ✓";

    # A String yields one code point at a time, as a one-code-point String.
    var count = 0;
    var copy = "";
    for (var c in word) {
        assert(c.length() == 1, "each piece is one code point");
        copy.append(c);
        count = count + 1;
    }
    assert(count == 7, "7 code points");
    assert(copy == word, "the pieces rebuild the string");

    # Each piece is the same value as indexing the string.
    var i = 0;
    for (var c in word) {
        assert(c == word[i], "same as word[i]");
        i = i + 1;
    }

    # An empty string runs the body zero times.
    for (var c in "") {
        assert(false, "never runs");
    }
    return 0;
}

The iterator protocol

The for loop is not tied to Array and String. It works with any type that has the right methods, described by two traits in the runtime (runtime/iterator.pep, documented in the Iterators reference):

export trait Iterator<T> {
    bool next();     # advance; true if there is a current element
    T current();     # the element next() just moved to
}

export trait Iterable<T> {
    iterate(): Iterator<T>;
}
  • An iterator steps through elements. next() moves to the next element and returns true, or returns false when there are no more (and keeps returning false after that). current() returns the element next() moved to.
  • An iterable is a collection that hands out a fresh iterator from iterate(). Array<T> returns an ArrayIterator<T> and String returns a StringIterator.

for (var x in source) { body } behaves exactly like this:

{
    var it = source.iterate();   # or `var it = source;` when source is itself an iterator
    while (it.next()) {
        var x = it.current();
        { body }
    }
}

The loop chooses by the methods the source’s type has, like a C++ range-based for: it uses iterate() if the type has one, and otherwise uses the source itself as the iterator if it has both next() and current(). A type with neither is a compile error:

main.pep:4:19: error: type 'Foo' is not iterable: implement Iterable<T> (iterate()) or Iterator<T> (next() and current())
    4 |     for (var x in f) {
      |                   ^

HashMap and HashSet do not implement the protocol yet, so they cannot be used in a for loop.

Writing your own iterator

To make your own type work in a for loop, give it next() and current() (an iterator), or give it an iterate() method that returns such a type (an iterable):

# An iterator: next() advances, current() returns the element.
struct Countdown {
    int Remaining;
    int Now;

    construct(this.Remaining = 0) {}

    bool next() {
        if (Remaining == 0) {
            return false;
        }
        Now = Remaining;
        Remaining = Remaining - 1;
        return true;
    }

    int current() {
        return Now;
    }
}

# Declaring the trait documents the intent; the loop goes by the methods.
extend Countdown with Iterator<int> {}

# An iterable: iterate() hands out a fresh iterator for each loop.
struct Evens {
    int Limit;

    construct(this.Limit = 0) {}

    EvensIterator iterate() {
        var it = EvensIterator();
        it.Limit = Limit;
        it.Now = -2;
        return it;
    }
}

struct EvensIterator {
    int Limit;
    int Now;

    bool next() {
        Now = Now + 2;
        return Now < Limit;
    }

    int current() {
        return Now;
    }
}

extend EvensIterator with Iterator<int> {}
extend Evens with Iterable<int> {}

# A generic function can loop over any type that supports the protocol.
sum<C>(C values): int {
    var total = 0;
    for (var v in values) {
        total = total + v;
    }
    return total;
}

main(): int {
    var total = 0;
    for (var n in Countdown(3)) {
        total = total + n;
    }
    assert(total == 6, "3 + 2 + 1");

    # A loop over an iterator in a variable uses that object up.
    var c = Countdown(2);
    for (var n in c) {
        total = total + n;
    }
    assert(!c.next(), "the countdown is exhausted");

    # An iterable starts a new pass every time.
    var evens = Evens(10);
    assert(sum<Evens>(evens) == 20, "0 + 2 + 4 + 6 + 8");
    assert(sum<Evens>(evens) == 20, "a second pass sees the same elements");

    var nums = Array<int>();
    nums.append(30);
    nums.append(12);
    assert(sum<Array<int>>(nums) == 42, "arrays work too");
    return 0;
}

Some things to keep in mind:

  • Declaring the trait is optional. The loop looks only at which methods a type has. Writing extend Countdown with Iterator<int> {} documents your intent, and the compiler then checks that Countdown has both next() and current() (see Traits and extensions). Declaring it also lets the type be used as an Iterator<int> value, and a for loop over such a value calls the methods through the trait.
  • Looping over an iterator uses it up. When the source is itself an iterator stored in a variable, the loop drives that same object, so it is exhausted afterwards. An iterable starts a new, independent pass every time you loop over it.
  • Generic code can loop over a type parameter; each specialization checks the protocol for its own type (see Generics).
  • Calling current() out of turn panics in the runtime’s iterators: before the first next() you get ArrayIterator.current() before next(), and after next() returned false you get ArrayIterator.current() past the end. Your own iterators should follow the same rule.

Modifying a collection while you loop over it

Changing an Array or a String while a loop is iterating over it stops the program with a panic, because the iterator could otherwise skip or repeat elements, or read past the end:

var nums = Array<int>();
nums.append(1);
nums.append(2);
for (var x in nums) {
    nums.append(x);   # panics: Array modified during iteration
}

Every method that changes an Array counts, including storing an element with nums[i] = v. For a String, append and grow count, and the message is String modified during iteration. The check happens on the iterator’s next step, so modifying the collection after the loop is finished is fine.

To change elements as you go, loop over an index with while and store through it, or collect the changes in a second array and apply them after the loop.

Loop scope

The loop variable and anything declared in the loop body exist only inside the loop. Each pass gets a new loop variable, and struct values declared in the body are released at the end of every pass, whether the pass ends normally or by continue, break, or return. Leaving the loop early also releases the hidden iterator, so a destructor on a custom iterator runs at that point.

Using the loop variable or a body local after the loop is an error, the same as for any name that is out of scope:

main.pep:6:12: error: use of undeclared identifier 'i'
    6 |     return i;
      |            ^

The loop variable, or a local in the loop body, may have the same name as a variable declared before the loop. It hides the outer variable inside the loop, and the outer variable keeps its value afterwards.
