The Pepper Programming Language

Compression and archives

The compress module compresses and decompresses DEFLATE data, plain or in its zlib and gzip framings, and the archive module reads and writes tar archives. Together they handle .gz and .tar.gz files. Both are written in Pepper, so a program that uses them links no extra library, unless it is built to use zlib (see Using zlib).

# Compress and decompress bytes in one call, or as streams.
import compress;
import io;

main(): int {
    var text = "the cat sat on the mat; ".repeat(100).bytes();

    # gzip, zlib and raw DEFLATE each have compress and decompress.
    var packed = compress.Gzip.compress(text);
    assert(packed.count < text.count / 10, "repetitive text shrinks");
    assert(compress.Gzip.decompress(packed).value() == text, "round trip");

    # Level 0 stores, 9 squeezes hardest; 6 is the default.
    var fast = compress.Zlib.compress(text, level = 1);
    assert(compress.Zlib.decompress(fast).value() == text, "any level reads back");

    # Corrupt data is an error, never a crash.
    packed[packed.count - 5] = packed[packed.count - 5] ^ 1;
    var bad = compress.Gzip.decompress(packed);
    assert(bad.is_err() && bad.error().is_invalid_input(), "the CRC-32 check fails");

    # Streams: a CompressWriter wraps any io.Writer, a DecompressReader any
    # io.Reader, such as a File. Here both are in memory.
    var sink = io.ByteWriter();
    var writer = compress.CompressWriter(sink, compress.Format.Gzip);
    writer.print_line("first line");
    writer.print_line("second line");
    writer.finish();

    var reader = compress.DecompressReader(io.ByteReader(sink.bytes), compress.Format.Gzip);
    var lines = 0;
    for (var line in reader.lines()) {
        lines += 1;
    }
    assert(lines == 2, "two lines");

    # The checksums are there on their own too.
    assert(compress.Crc32.of("123456789".bytes()) == 0xCBF43926, "CRC-32");
    return 0;
}

Formats

FormatStructWhere it is used
Format.Gzipcompress.Gzip.gz files, HTTP Content-Encoding: gzip
Format.Zlibcompress.ZlibPNG images, HTTP deflate
Format.Rawcompress.Deflatezip entries, other containers with their own framing
  • compress(data, level = 6) returns the compressed bytes. The level runs from 0 (stored, no compression) to 9 (smallest, slowest). Each level searches for matches with zlib’s settings for it, so the output is about the size zlib makes at the same level, at a similar speed: on 12 MB of source text, compressing at level 6 takes about 1.2 times as long as the gzip command, and decompressing is a little faster than gzip -d.
  • decompress(data) returns an io.IoResult<u8[]>. Damaged or truncated data is an error whose is_invalid_input() holds, and gzip and zlib data is checked against its CRC-32 or Adler-32 checksum.
  • Gzip input may hold several members one after another (cat a.gz b.gz); they decompress to their contents joined. Bytes after the last member are an error. A gzip header’s file name and comment are skipped, and a written header has neither.
  • A zlib stream that needs a preset dictionary is not supported.
  • decompress puts everything in memory. Use a DecompressReader for input from outside the program, so a small file that expands hugely cannot exhaust memory.

compress.Crc32 and compress.Adler32 compute the two checksums over data given in pieces (update, then value), or in one call with of.

Streams

compress.DecompressReader(source, format) is an io.Reader that decompresses source, any io.Reader, as it is read, so lines(), chunks(size) and read_all() work on it. It holds at most about 225 KiB of input and output, however large the data.

compress.CompressWriter(sink, format, level = 6) is an io.Writer that compresses what is written and writes the result to sink. Call finish() at the end: it writes the last block and the checksum. Dropping the writer does not finish it, and finish() does not close the sink.

io.ByteReader(bytes) and io.ByteWriter() stand in for a stream when the data is in memory.

Using zlib

Building with -D USE_ZLIB (see Build options) makes compress use zlib, the reference DEFLATE library, for compressing, decompressing, CRC-32 and Adler-32, in place of its Pepper code:

pep-build main.pep -D USE_ZLIB -o app
  • The API is the same, and so are the errors for damaged data, worded as the Pepper code words them where zlib tells the causes apart. Compressed output can differ byte for byte (zlib’s gzip header names the operating system), but each side decompresses the other’s.
  • Linux links -lz, from the development package (zlib1g-dev, zlib-devel). macOS has zlib already. Windows has none: install it (vcpkg install zlib) and name the folder holding zlib.lib with -L or PEPPER_LIBRARY_PATH.
  • zlib compresses faster than the Pepper code at the same level, and makes output of about the same size.

Tar archives

# Write a .tar.gz, list it, and extract it.
import archive;
import compress;
import io;

main(): int {
    var folder = io.Directory.temp().join("pepper-compression-tar-example");
    io.Directory.remove_all(folder);
    var path = io.Directory.temp().join("pepper-compression-tar-example.tar.gz");

    # A TarWriter over a gzip CompressWriter over a File.
    var file = io.File.create(path).value();
    var gzip = compress.CompressWriter(file, compress.Format.Gzip);
    var tar = archive.TarWriter(gzip);
    tar.append_directory("app-1.0");
    tar.append_file("app-1.0/main.pep", "main(): int { return 0; }\n".bytes());
    tar.append_file("app-1.0/run.sh", "#!/bin/sh\n".bytes(), mode = 493);
    tar.finish();
    gzip.finish();
    file.close();

    # List the entries.
    var reader = archive.TarReader(compress.DecompressReader(io.File.open(path).value(), compress.Format.Gzip));
    var names = Array<String>();
    while (true) {
        var entry = reader.next_entry().value();
        if (entry.is_empty()) {
            break;
        }
        names.append(entry.value().path);
    }
    assert(names.count == 3 && names[0] == "app-1.0/", "a directory ends with '/'");

    # Extract without the top directory.
    reader = archive.TarReader(compress.DecompressReader(io.File.open(path).value(), compress.Format.Gzip));
    reader.extract(folder, strip_components = 1).value();
    assert(io.File.read_to_string(folder.join("main.pep")).value().starts_with("main"), "extracted");

    io.Directory.remove_all(folder);
    io.File.remove(path);
    return 0;
}

archive.TarReader(source) reads an archive from any io.Reader; wrap the file in a DecompressReader to read a .tar.gz.

  • next_entry() moves to the next entry and returns its TarEntry: path, kind (File, Directory, Symlink, HardLink or Other), size, mode, modified (seconds since 1970) and link_target. It returns Empty at the end of the archive.
  • The reader is an io.Reader of the current entry’s contents: read, read_all(), lines(). Contents not read are skipped.
  • It reads ustar archives with the pax and GNU extensions for long paths, which covers GNU tar, bsdtar, and the .tar.gz snapshots that git archive, GitHub, GitLab and Codeberg make.

extract(target, strip_components = 0) writes the rest of the archive into the directory target:

  • It refuses, with an is_invalid_input() error, an entry whose path is absolute or holds a .. component, a \ or a :, so an archive cannot write outside target.
  • strip_components drops leading path components, as tar’s --strip-components does. A GitHub snapshot puts everything under name-version/, which strip_components = 1 removes.
  • Files and directories are created. A hard link becomes a copy of the file it names. Symlinks, devices and FIFOs are skipped.
  • Permission bits and modification times are not applied yet: extracted files get the default permissions, so a script loses its executable bit.

archive.TarWriter(sink) writes an archive: append_file(path, data), append_directory(path), append_symlink(path, target), append(entry, data) for any header, and append_stream(entry, source) to copy entry.size bytes from a stream. finish() writes the end marker. Paths longer than a ustar header holds get a pax header, so none is cut short. .zip archives are not supported yet.
