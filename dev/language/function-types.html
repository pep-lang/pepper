The Pepper Programming Language

Function types and closures

Functions in Pepper are values. You can store a function in a variable, a field or an array, pass it to another function, and return it. This lets you choose behavior at run time: a sort order, a callback, a step in a pipeline. A function value is a named function, a method, a constructor, or a closure: an anonymous function written where it is used.

Function types

A function type is written (parameter types) => return type:

TypeMeaning
(int) => inttakes an int, returns an int
(String, int) => booltakes a String and an int, returns a bool
() => voidtakes nothing, returns nothing
(int) => (int) => inttakes an int, returns an (int) => int

=> is right-associative, so the last row is a function that returns a function. A function type can be used anywhere a type can: for variables, parameters, return types, struct fields, generic arguments such as Array<(int) => int>, and type aliases.

Written with shared in front, as in shared () => void, a function type is thread-safe: its values can be passed to other threads. See Sharing function values between threads.

Referring to a named function

The name of a free function, written without a call, is a value of that function’s type. Calling a function value calls the function:

# Function types and references to named functions.
square(x: int): int { return x * x; }
negate(x: int): int { return -x; }

# A parameter can take a function: its type is '(parameter types) => return type'.
apply(f: (int) => int, x: int): int {
    return f(x);
}

twice(f: (int) => int, x: int): int {
    return f(f(x));
}

# Generic functions can take function values too.
apply_twice<T>(f: (T) => T, x: T): T {
    return f(f(x));
}

main(): int {
    # A function's name without a call is a value of its function type.
    var f = square;                 # f: (int) => int
    assert(f(3) == 9, "call through a local");

    var g: (int) => int = negate;   # the type can be written out
    assert(g(4) == -4, "explicit function type");

    # Function variables can be reassigned to another function of the same type.
    f = negate;
    assert(f(6) == -6, "reassigned");

    assert(apply(square, 5) == 25, "pass a function as an argument");
    assert(twice(square, 3) == 81, "(3 * 3) * (3 * 3)");
    assert(twice(negate, 7) == 7, "negating twice");
    assert(apply_twice<int>(square, 2) == 16, "generic");
    return 0;
}
  • var f = square; infers f’s type, (int) => int, from the function. An overloaded name, or an overloaded method (p.move), needs a declared type instead, which picks the member.
  • A function-typed variable can be reassigned to any function of the same type.
  • A parameter of function type, such as f: (int) => int, lets the caller pass in the behavior. Generic functions can take function parameters too.

Methods, constructors and generic functions

Methods, constructors and specializations of generic functions are values too:

# Methods, constructors and generic functions used as values.
struct Point {
    int x;
    int y;
    construct(this.x = 0, this.y = 0) {}

    norm(): int {
        return x + y;
    }

    shifted(dx: int): Point {
        return Point(x + dx, y);
    }
}

larger<T>(a: T, b: T): T {
    return a > b ? a : b;
}

combine(f: (int, int) => int, a: int, b: int): int {
    return f(a, b);
}

main(): int {
    var p = Point(3, 4);

    # A bound method: the method of one object, which it keeps alive.
    var norm = p.norm;
    assert(norm() == 7, "bound method");

    # An unbound method takes the object as its first argument.
    var norm_of: (Point) => int = Point.norm;
    assert(norm_of(Point(1, 1)) == 2, "unbound method");

    # A struct's name is its constructor.
    var make: (int, int) => Point = Point;
    assert(make(5, 6).y == 6, "constructor");

    # A generic function with its type arguments names one specialization.
    assert(combine(larger<int>, 2, 9) == 9, "generic function");

    var steps = Array<(int) => Point>();
    steps.append(p.shifted);
    steps.append(Point(10, 0).shifted);
    assert(steps[1](5).x == 15, "methods in an array");
    return 0;
}
WrittenTypeCalls
p.norm() => intp.norm(), on the object p referred to when the value was made
Point.norm(Point) => intnorm on the object passed as the first argument
Point.origin (a static method)() => PointPoint.origin()
Point(int, int) => Pointthe constructor
Box<int>(int) => Box<int>the constructor of Box<int>
larger<int>(int, int) => intthe specialization larger<int>
  • Bound methods. p.norm keeps a reference to the object, like a closure () => p.norm() that captured p, so the object lives as long as the value does. The expression before the . is evaluated once, when the value is made. Inside a method, write this.norm; a bare norm is not a value. Storing this.norm in a field of this would be a reference cycle, and is an error, as for closures.
  • Traits and extensions. A method declared in an extension works the same way, and so does a method of a trait-typed value (shape.area), which calls through the trait.
  • Generic functions need their type arguments: larger<int>, not larger.
  • A type with a constructor that takes no arguments. Box<int> on its own names the constructor only when the constructor needs at least one argument; otherwise it is a call, Box<int>(). The same goes for a generic function whose parameters all have defaults.

Storing and returning functions

Function values go wherever other values go: struct fields, arrays, module-level variables and return values. A type alias gives a long function type a short name, and can have type parameters of its own.

# Function values in fields, arrays, globals, and return values.

import async;

square(x: int): int { return x * x; }
negate(x: int): int { return -x; }
increment(x: int): int { return x + 1; }

struct Transform {
    var op: (int) => int;
    construct(this.op = square) {}
    run(x: int): int { return op(x); }
}

# Choose a function at run time and return it.
pick(squared: bool): (int) => int {
    if squared {
        return square;
    }
    return negate;
}

# A module-level function variable. Every module-level variable is const
# and thread-safe: an Atomic lets it change, and a function type every thread
# can reach is declared shared.
const handler = async.Atomic<shared (int) => int>(increment);

# A type alias can name a function type, even a generic one.
type Combine<T> = (T, T) => T;
add(a: int, b: int): int { return a + b; }
fold(values: int[], combine: Combine<int>, start: int): int {
    var total = start;
    for (var v in values) {
        total = combine(total, v);
    }
    return total;
}

# A function that returns nothing has the return type void.
const events = async.Atomic<int>(0);
record(n: int) { events.fetch_add(n); }

main(): int {
    var t = Transform();
    assert(t.run(4) == 16, "the default op squares");
    t.op = negate;
    assert(t.op(4) == -4, "call through a field");

    var pipeline = Array<(int) => int>();
    pipeline.append(increment);
    pipeline.append(square);
    pipeline.append(negate);
    var value = 2;
    for (var step in pipeline) {
        value = step(value);
    }
    assert(value == -9, "-((2 + 1) * (2 + 1))");
    assert(pipeline[1](5) == 25, "call an array element");

    assert(pick(true)(5) == 25, "call a returned function directly");
    var chosen = pick(false);
    assert(chosen(5) == -5, "call a stored returned function");

    assert(handler.load()(1) == 2, "global function value");
    handler.store(square);
    assert(handler.load()(3) == 9, "replaced global");

    var numbers = Array<int>();
    numbers.append(1);
    numbers.append(2);
    numbers.append(3);
    assert(fold(numbers, add, 10) == 16, "10 + 1 + 2 + 3");

    var callback: (int) => void = record;
    callback(2);
    callback(5);
    assert(events.load() == 7, "void function values");
    return 0;
}
  • Fields. A field of function type is called like a method: t.op(4). Inside the struct, op(x) and this.op(x) both call it.
  • Arrays. pipeline[1](5) indexes the array and calls the element.
  • Module-level variables. Every module-level variable is const and thread-safe (see Module-scope variables), so one whose function changes is an Atomic of a shared function type: handler.load()(1) calls the current function and handler.store(square) replaces it.
  • Return values. pick(true)(5) calls the function that pick returns.
  • void results. A function without a return value has a function type ending in => void, such as (int) => void.

Closures

A closure literal is a parameter list, =>, and a body. The body is an expression or a block:

# Closure literals: anonymous functions that capture values.
struct Counter {
    int count;
    construct(this.count = 0) {}
    add(n: int) { count += n; }
}

apply(f: (int) => int, x: int): int {
    return f(x);
}

# A closure can outlive the function that made it: it keeps its own copy
# of 'n'.
make_adder(n: int): (int) => int {
    return (x) => x + n;
}

struct Scaler {
    int factor;
    construct(this.factor = 1) {}

    # Inside a method, a closure can use 'this' and the struct's members.
    scaler(): (int) => int {
        return (x) => x * factor;
    }
}

main(): int {
    # Parameter types written out: the closure's type is (int) => int.
    var double = (x: int) => x * 2;
    assert(double(21) == 42, "expression body");

    # With a function type to fill, the parameter types can be left out.
    var add: (int, int) => int = (a, b) => a + b;
    assert(add(40, 2) == 42, "types from the variable");
    assert(apply((x) => x * x, 5) == 25, "types from the parameter");

    # A block body, with the return type written after the parameters.
    var clamp = (x: int, low: int, high: int): int => {
        if x < low { return low; }
        if x > high { return high; }
        return x;
    };
    assert(clamp(7, 0, 5) == 5, "block body");

    # Captured values.
    var add_five = make_adder(5);
    assert(add_five(10) == 15, "captured parameter");
    var offset = 100;
    var shift = (x: int) => x + offset;
    assert(shift(1) == 101, "captured local");

    # A captured struct is shared, so the closure can change the object.
    var counter = Counter();
    var bump = () => counter.add(1);
    bump();
    bump();
    assert(counter.count == 2, "shared struct");

    var triple = Scaler(3).scaler();
    assert(triple(4) == 12, "captured this");

    # A closure can return a closure.
    var adder: (int) => (int) => int = (a) => (b) => a + b;
    assert(adder(2)(3) == 5, "curried");
    return 0;
}

  • Parameter types. (x: int) => x * 2 writes the parameter type. When the closure goes straight into a slot of function type (a typed variable, a parameter, an assignment, a return, a field), the types come from that slot, so (a, b) => a + b is enough. A parameter of a generic function counts too: passing (x) => x + 1 to apply<T>(f: (T) => T, x: T) with x an int types the closure’s x as int (see Generics). With no slot to take them from, a parameter without a type is an error:

    main.pep:2:14: error: cannot infer the type of parameter 'x'; write it: (x: Type) => ...

  • Return type. It is inferred from the body, or from the slot. To write it, put it after the parameters: (x: int): long => x.

  • Body. An expression body is the value the closure returns. A block body uses return like a function. A closure whose type returns void can have an expression body such as () => counter.add(1); the value is discarded.

  • Calling. A closure is called like any function value, and can be called where it is written: ((x: int) => x + 1)(2).

Captured values

A closure can use the local variables and parameters around it. It keeps a copy of each one it uses, made when the closure is created, so it can outlive the function that created it (make_adder above).

A captured variable must never be assigned, before or after the closure is created, inside the closure or outside it. Then the copy and the variable can never differ:

var count = 0;
var f = () => count;
count = 5;   # error

main.pep:4:5: error: cannot assign to 'count' because a closure captures it
main.pep:3:19: note: captured here; a closure keeps a copy, so the variable must not change

The rule applies to ++, -- and compound assignments too. Only the variable is fixed: a captured struct is a reference to the same object, so the closure can call its methods and change its fields (counter above). To share a changing number, capture a struct that holds it, such as a Counter or an Atomic<int>.

this in methods

A closure written in a method can use this, the struct’s fields and its methods. It captures this (one reference to the object), never a copy of the fields, so it sees the fields’ current values.

Storing such a closure in a field of the same object would make the object and the closure keep each other alive forever (a reference cycle), so that direct case is an error:

main.pep:4:15: error: storing a closure that captures 'this' in field 'measure' of 'this' creates a reference cycle that is never freed

Capture a weak reference to the object instead.

Type checking

A function value must match the type it flows into exactly: the same parameter types in the same order and the same return type. The aliases of a primitive type count as the same type, so (i32) => i32 and (int) => int match. A mismatch in an initializer, an assignment, an argument or a return is a compile error, as is calling a function value with the wrong number of arguments:

square(x: int): int { return x * x; }

main(): int {
    var f: (String) => int = square;   # error
    return f(1, 2);                    # error
}

error: variable 'f' expects a function of type (String) => int, but was given a function of type (int) => int
a function of type (String) => int takes 1 argument(s), but 2 were given

These two errors do not show a source location yet.

Sharing function values between threads

A plain function type such as () => void can hold any function value, including a closure that captures a String or an Array. Such values stay on the thread that made them: their reference counts are plain increments, like those of a struct that is not [Shared] (see What threads can share).

A function type written with shared in front, such as shared () => void or shared (long) => void, is thread-safe. Its reference counts are atomic, and its values hold only thread-safe state, so any thread may copy, call and drop them. It goes wherever a thread-safe type is required: the body of a thread (ThreadBody is shared () => void), a field of a [Shared] struct, a module-scope variable, or async.Atomic<shared (int) => int>.

# shared function types: function values that threads can share.
import async;

const total = async.Atomic<long>(0);

# A named function holds no state, so it is always thread-safe.
add_one() {
    total.fetch_add(1);
}

# A [Shared] struct's fields must be thread-safe: a function field is shared.
[Shared]
struct Task {
    const weight: long;
    const run: shared (long) => void;
    construct(this.weight = 1, this.run = (n: long) => {}) {}
}

# A plain function type takes any function of the same signature.
apply(f: (long) => long, x: long): long {
    return f(x);
}

main(): int {
    # A closure converts to a shared type when everything it captures is
    # thread-safe: here nothing but the module-scope Atomic.
    var add: shared (long) => void = (n: long) => { total.fetch_add(n); };
    var task = Task(10, add);

    # A thread body is a shared () => void. This closure captures a
    # [Shared] struct.
    var worker = async.Thread.spawn(() => { task.run(task.weight); });
    var other = async.Thread.spawn(add_one);
    worker.join();
    other.join();
    assert(total.load() == 11, "both threads ran");

    # A shared value can be used where a plain one is expected.
    var step: long = 5;
    var add_step: shared (long) => long = (x: long) => x + step;
    assert(apply(add_step, 1) == 6, "shared value passed as plain");

    # A plain closure may capture anything, but stays on this thread.
    var name = "worker";
    var greet = () => name + " done";
    assert(greet() == "worker done", "plain closure");
    return 0;
}

  • What converts to shared. A named function, which holds no state; a method, constructor or generic function value with nothing captured, such as Point.norm or Box<int>; and a closure literal (or a bound method such as p.norm) whose captured values are all thread-safe: numbers, Atomic<T> and other [Shared] structs, shared function values, and the rest of that list. The value must be written where the shared type is expected, so that it is made thread-safe from the start.

  • What does not. A closure that captures a value that is not thread-safe is reported at the capture, with a note at the captured variable:

    main.pep:5:46: error: closure passed as 'shared () => void' captures 'name' of type 'String', which is not thread-safe
    5 |     var t = async.Thread.spawn(() => { print(name); });
      |                                              ^~~~
main.pep:4:9: note: capture a thread-safe value instead, such as an 'async.Atomic<T>' or a '[Shared]' struct
    4 |     var name = "worker";
      |         ^~~~

    A closure in a method that uses this or a member captures this, so it is thread-safe only in a [Shared] struct. A value that already has a plain type (a variable, a parameter, a call result) never becomes shared, even when it holds nothing:

    main.pep:3:32: error: cannot initialize variable 'f' of type 'shared () => void' with a value of type '() => void'
    3 |     var f: shared () => void = g;
      |                                ^

  • From shared to plain. A shared value converts to the plain type of the same signature anywhere: shared (long) => long can be passed to a parameter of type (long) => long. The conversion allocates a small plain function value that holds the shared one and calls it, so the plain copy counts with plain increments while the shared value keeps its atomic ones.

  • Inference. A variable initialized with a closure, such as var f = () => 1;, has a plain type. Write the type to make it shared: var f: shared () => int = () => 1;.

  • shared is special only directly before a function type; elsewhere it is an ordinary name.

Null function values

A function-typed variable or field that has never been assigned is null. Calling it stops the program with the message called a null function value:

var handler: (int) => int;
handler(1);   # panics: called a null function value

Names and shadowing

A local variable, parameter or field with the same name as a free function hides the function inside its scope. Inside a function with a parameter named square, square means the parameter, not the function.

Memory

A function value is a reference, like a struct value, and follows the same reference-counting rules (see Memory and reference counting). Referring to a named function allocates nothing: every reference to square shares one static function object. A method, constructor or generic function value allocates one small object, like a closure; a bound method’s object holds a reference to its receiver.

Creating a closure allocates one object holding the captured values, like constructing a struct. Copying the closure adds a reference to that object, and when the last reference goes, the object releases what it captured.

A plain function value’s counts are plain increments; a shared one’s are atomic, like a [Shared] struct’s (see Sharing function values between threads).

What is not supported yet

  • Generic functions without type arguments and extern functions cannot be referenced as values. larger alone is not a value even where the expected type would pick larger<int>. To use an extern function as a value, wrap it in a closure: (x: int) => abs(x).
  • Generic methods cannot be referenced as values: b.map<long> is not a value. Wrap the call in a closure: (f: (int) => long) => b.map(f).
  • A bare method name inside a method (var f = norm;) is not a value; write this.norm.
  • Closures in trait default methods cannot use this or the members of the struct yet.
  • Closures that capture values as C callbacks. A C function pointer (extern (P) => R) takes a named function or a closure that captures nothing; see Calling C.
