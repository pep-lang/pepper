**Pitfalls.**
- Layered builds must keep `record_summaries` on, because the interface hashes depend on it. `build_cache_test` covers early cutoff.
- The self-build edit only appends a comment, so it can't catch early-cutoff bugs. Run build_cache_test for those.
- Check correctness by comparing 265 programs built layered against `--no-cache`. Four diffs are expected: os-environment, os-time, platform-externs and time-zones.
- Never time two builds at once. Wall time varies by about ±1 s, so use the median of 3 runs.
- Big integer constants need literals: `60*60*1000000000` overflows int.
- Codegen must always emit `main`, because the entry part defines it.

**Commands.**
- Build pepc: `cd tools && PEPPER_RUNTIME=$PWD/../runtime PEPPER_CACHE_DIR=<dir> <old pepc> -O2 -I . compiler/main.pep -o <new>`
- Frame-pointer build for perf: `../target/release/pep-build -O --frame-pointers -I . compiler/main.pep -o X --build D`

- Checks: `cargo build --release`; `scripts/pepper-tests.sh`; `target/release/pep-doc check`; `target/release/pep-fmt --check runtime tools`.
