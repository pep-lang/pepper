The Pepper Programming Language

Parser

Parser and the handles its declarations return: Flag, Argument and ArgumentList.

Source: runtime/cli/parser.pep

Parser

struct Parser

Declares a program's command-line interface and parses its arguments.

Declare each option and positional argument with flag, option, multiple, positional and positionals; each returns a handle that reads its value once parse has run. parse also writes the help (--help), the version (--version) and clang-style errors, all from the declarations.

Options have a long name (--output), a one-letter short name (-o), or both. A value follows as --output a.out, --output=a.out, -o a.out or -oa.out; short flags combine (-vq is -v -q), and -- ends the options, so every argument after it is positional. A value is taken as it is, even when it starts with -. An option declared with an implicit_value takes a value only when it is attached (--emit-ast=json, -O3), and the implicit one when it is not. When an option that takes one value is given twice, the last value wins.

Subcommands (git add, pep-package update) are parsers of their own, made with command. Options before the command's name belong to this parser, and everything after it to the command's.

Example

import cli;

main(args: String[]): int {
    var parser = cli.Parser("pepper", "Compiles a Pepper program", version = "0.2.1");
    var output = parser.option("output", "o", "the executable to write", default_value = "a.out");
    var imports = parser.multiple("import-path", "I", "a directory to search for modules");
    var verbose = parser.flag("verbose", "v", "say what is happening");
    var source = parser.positional("source", "the program's entry file");
    if (!parser.parse(args)) {
        return 2;
    }
    print($"{source.value()} -> {output.value()}");
    return 0;
}

option

option<T>( name: String, short_name: String = "", help: String = "", value_name: String = "", default_value: String = "", required: bool = false, global: bool = false, implicit_value: String = "" ): Argument<T>

Declares an option that takes one value of type T, such as --jobs 4 for option<int>. A value that does not read as a T fails the parse: invalid value 'x' for '--jobs': expected an integer.

T may be String, an integer type, float, double, io.Path, or an enum whose cases carry no values; a case is written in kebab case (DebugInfo is debug-info), and the help lists them.

Type parameters

  • T — the type of the value

Parameters

  • name — the long name, without --, or empty for an option with only a short name (-I)
  • short_name — the one-letter short name, without -, or empty for none
  • help — what the option sets, for the help
  • value_name — what the help calls the value; empty for the long name in capitals (JOBS)
  • default_value — the value when the option is not given, written as on the command line ("4"); empty for none
  • required — whether leaving the option out is an error
  • global — whether the option may also be given after the name of a command, at any depth
  • implicit_value — the value when the option is given without one, written as on the command line (-O alone as -O2); when not empty, a value must be attached (--name=value, -xvalue) and the next argument is never taken as one

Returns

  • the handle that reads the value

Panics

  • if name or short_name is invalid or already declared, or if default_value or implicit_value does not read as a T

Example

var jobs = parser.option<int>("jobs", "j", "how many at once", default_value = "4");

command

command(name: String, about: String = ""): Parser

Declares a subcommand, such as add in pep-package add NAME, and returns its parser, on which to declare its own options and arguments.

A parser with commands requires one: the first argument that is not an option names it, and the arguments after it go to its parser. After parse, is_selected on the command's parser tells whether it was the one given.

Parameters

  • name — the command's name
  • about — what the command does, for the help

Returns

  • the command's parser

Panics

  • if name is empty, starts with - or is already declared, or if this parser has positional arguments

add_options

add_options<T>(options: T)

Declares an option or positional argument for each public field of options, and has every successful parse store the values in those fields.

A field's type picks what it declares: bool is a flag, String an option with one value, String? one that may be left out, and String[] one that may be given many times. An option is named after its field, with each _ written - (import_path is --import-path); [cli.Option] on a field gives it a short name, help, another name, or makes it required. [cli.Positional] makes a field the next positional argument instead.

A String field that holds a value when this is called keeps it as the default; an empty one has no default, so leaving the option out leaves it empty, or is an error for a positional argument. Every parse sets every field: a flag to whether it was given, a list to the values given.

The declarations are the same as the builder methods make, so the help and errors read the same, and the two styles mix on one parser.

Type parameters

  • T — the options struct

Parameters

  • options — the struct whose fields to declare and fill in

Example

import cli;

struct Options {
    [cli.Option("o", "the executable to write")]
    var output: String = "a.out";
    [cli.Option("v", "say what is happening")]
    var verbose: bool;
    [cli.Positional("the program's entry file")]
    var source: String;
}

main(args: String[]): int {
    var options = Options();
    var parser = cli.Parser("pepper", "Compiles a Pepper program");
    parser.add_options(options);
    if (!parser.parse(args)) {
        return 2;
    }
    print($"{options.source} -> {options.output}");
    return 0;
}

usage

Returns the one-line usage, such as usage: pepper [OPTIONS] <source>.

Returns

  • the usage line, without a line break

help

help(): String

Returns the help that --help prints: what the program does, the usage, and a line for each argument, option and command.

Returns

  • the help text, ending in a line break

completions

completions(shell: Shell): String

Returns a script that completes this program's command line in shell: its options, commands and enum choices, and file names where a value is a String or an io.Path. A program usually prints it from a command of its own (pkg completions bash), for the user to install where Shell's cases say.

Call it on the program's parser, after the declarations.

Parameters

  • shell — the shell the script is for

Returns

  • the script, ending in a line break

Example

var parser = cli.Parser("pkg");
var shell = parser.option<cli.Shell>("completions", help = "print a completion script");
if (!parser.parse(args)) {
    return 2;
}
if (shell.is_set) {
    print(parser.completions(shell.value()));
}

try_parse

try_parse(args: String[]): Result<String?>

Parses args and fills in every handle, or reports the problem.

Writes nothing. Use it to handle errors, help and the version yourself; parse does it the usual way.

Parameters

  • args — the arguments as main receives them: the program's name, then its arguments

Returns

  • some text when --help or --version was given (the program should print it and exit with 0), none when the arguments were parsed, or an error when they are wrong, with a clang-style message such as missing value for '-o'

parse

parse(args: String[]): bool

Parses args and fills in every handle.

For --help or --version it prints the text to standard output and ends the program with status 0. When the arguments are wrong it writes the error, the usage and a hint to standard error, such as

pepper: error: missing value for '-o'
usage: pepper [OPTIONS] <source>
Run 'pepper --help' for more information.

and returns false; exit with status 2, as the example does.

Parameters

  • args — the arguments as main receives them: the program's name, then its arguments

Returns

  • true when the arguments were parsed, false after an error

usage_error

usage_error(message: String): int

Writes a usage error found after parse, such as two options that cannot be used together, as parse writes one: the error, this parser's usage and a hint, to standard error.

Parameters

  • message — what is wrong, clang-style ('--test' cannot be used with '--lib')

Returns

  • 2, the status a program exits with after a usage error

Example

if (test.is_set and library.is_set) {
    return parser.usage_error("'--test' cannot be used with '--lib'");
}

closest

closest(name: String, candidates: Array<String>): String?

Returns the candidate closest to a misspelled name, for a "did you mean" suggestion: the one the fewest single-byte insertions, deletions and substitutions turn name into, when that is at most 2. Of equally close candidates the first wins.

Parameters

  • name — the name that matched nothing
  • candidates — the names it could have meant

Returns

  • the closest candidate, or none when none is within 2 edits

Example

var names = Array<String>();
names.append("build");
names.append("fmt");
var best = cli.closest("buidl", names);   # some("build")
